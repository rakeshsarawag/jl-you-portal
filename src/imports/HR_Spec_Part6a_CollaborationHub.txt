STEP 1 — NEW DATABASE TABLES
--------------------------------------------------------------------------------

TABLE: chat_channels
  id                UUID           PRIMARY KEY DEFAULT gen_random_uuid()
  name              TEXT           NOT NULL
  description       TEXT
  type              TEXT           NOT NULL  -- 'public' | 'private' | 'dm' | 'group_dm'
  created_by        UUID           REFERENCES app_users(id)
  created_at        TIMESTAMPTZ    DEFAULT now()
  archived_at       TIMESTAMPTZ    -- NULL = active
  last_message_at   TIMESTAMPTZ    -- updated on each new message (for sidebar sort)

TABLE: chat_channel_members
  id                        UUID        PRIMARY KEY DEFAULT gen_random_uuid()
  channel_id                UUID        REFERENCES chat_channels(id) ON DELETE CASCADE
  user_id                   UUID        REFERENCES app_users(id) ON DELETE CASCADE
  role                      TEXT        NOT NULL DEFAULT 'member'  -- 'admin' | 'member'
  joined_at                 TIMESTAMPTZ DEFAULT now()
  last_read_at              TIMESTAMPTZ -- used for unread count calculation
  notification_preference   TEXT        DEFAULT 'all'  -- 'all' | 'mentions' | 'nothing'
  UNIQUE (channel_id, user_id)

TABLE: chat_messages
  id                UUID        PRIMARY KEY DEFAULT gen_random_uuid()
  channel_id        UUID        REFERENCES chat_channels(id) ON DELETE CASCADE
  sender_id         UUID        REFERENCES app_users(id)
  content           TEXT        NOT NULL
  parent_message_id UUID        REFERENCES chat_messages(id)  -- NULL = root message
  edited_at         TIMESTAMPTZ -- NULL = never edited
  deleted_at        TIMESTAMPTZ -- NULL = not deleted (soft delete)
  created_at        TIMESTAMPTZ DEFAULT now()

TABLE: chat_message_reactions
  id          UUID        PRIMARY KEY DEFAULT gen_random_uuid()
  message_id  UUID        REFERENCES chat_messages(id) ON DELETE CASCADE
  user_id     UUID        REFERENCES app_users(id) ON DELETE CASCADE
  emoji       TEXT        NOT NULL
  created_at  TIMESTAMPTZ DEFAULT now()
  UNIQUE (message_id, user_id, emoji)

TABLE: chat_message_attachments
  id            UUID        PRIMARY KEY DEFAULT gen_random_uuid()
  message_id    UUID        REFERENCES chat_messages(id) ON DELETE CASCADE
  file_url      TEXT        NOT NULL   -- signed URL or storage path
  file_name     TEXT        NOT NULL
  file_size     BIGINT                 -- bytes
  file_type     TEXT                   -- MIME type
  thumbnail_url TEXT                   -- NULL for non-images
  uploaded_at   TIMESTAMPTZ DEFAULT now()

TABLE: user_presence
  id                  UUID        PRIMARY KEY DEFAULT gen_random_uuid()
  user_id             UUID        REFERENCES app_users(id) ON DELETE CASCADE UNIQUE
  status              TEXT        DEFAULT 'offline'  -- 'online' | 'away' | 'offline'
  last_seen_at        TIMESTAMPTZ DEFAULT now()
  custom_status_text  TEXT        -- e.g. "In a meeting"
  updated_at          TIMESTAMPTZ DEFAULT now()

Indexes (add for performance):
  chat_messages(channel_id, created_at)
  chat_messages(parent_message_id)
  chat_channel_members(user_id, channel_id)
  user_presence(user_id)

STEP 2 — REPLACE ChatService (localStorage) WITH SUPABASE CRUD
--------------------------------------------------------------------------------

FUNCTION: getAllChannels()
  supabase
    .from('chat_channels')
    .select('*, members:chat_channel_members(count)')
    .is('archived_at', null)
    .order('last_message_at', { ascending: false })

  Returns: channel list sorted by most-recent activity, with member count.

FUNCTION: getMyChannels(userId)
  supabase
    .from('chat_channels')
    .select('*, my_membership:chat_channel_members!inner(role, last_read_at, notification_preference)')
    .eq('chat_channel_members.user_id', userId)
    .is('archived_at', null)
    .order('last_message_at', { ascending: false })

FUNCTION: getMessages(channelId, limit = 50, before = null)
  supabase
    .from('chat_messages')
    .select(`
      *,
      sender:app_users(id, name, avatar_url),
      reactions:chat_message_reactions(*),
      attachments:chat_message_attachments(*),
      reply_count:chat_messages!parent_message_id(count)
    `)
    .eq('channel_id', channelId)
    .is('deleted_at', null)
    .order('created_at', { ascending: true })
    .limit(limit)

  For pagination: add .lt('created_at', before) when loading older messages.

FUNCTION: getThreadReplies(parentMessageId)
  supabase
    .from('chat_messages')
    .select('*, sender:app_users(id, name, avatar_url), reactions:chat_message_reactions(*), attachments:chat_message_attachments(*)')
    .eq('parent_message_id', parentMessageId)
    .is('deleted_at', null)
    .order('created_at', { ascending: true })

FUNCTION: sendMessage(channelId, content, parentId = null)
  const { data } = await supabase
    .from('chat_messages')
    .insert({
      channel_id: channelId,
      sender_id: currentUser.id,
      content: content.trim(),
      parent_message_id: parentId || null
    })
    .select()
    .single()

  After insert: update chat_channels.last_message_at = now() for channelId.

FUNCTION: editMessage(messageId, newContent)
  supabase
    .from('chat_messages')
    .update({ content: newContent.trim(), edited_at: new Date().toISOString() })
    .eq('id', messageId)
    .eq('sender_id', currentUser.id)   -- RLS enforced too

FUNCTION: deleteMessage(messageId)
  supabase
    .from('chat_messages')
    .update({ deleted_at: new Date().toISOString() })
    .eq('id', messageId)

  Soft delete: message row stays; content replaced with placeholder in UI.

FUNCTION: toggleReaction(messageId, emoji)
  -- Check if reaction already exists
  const existing = await supabase
    .from('chat_message_reactions')
    .select('id')
    .eq('message_id', messageId)
    .eq('user_id', currentUser.id)
    .eq('emoji', emoji)
    .maybeSingle()

  If exists: delete (toggle off)
    supabase.from('chat_message_reactions').delete().eq('id', existing.id)
  If not: insert (toggle on)
    supabase.from('chat_message_reactions').insert({ message_id, user_id, emoji })

FUNCTION: createChannel(name, description, type, memberIds = [])
  1. Insert into chat_channels
  2. Insert creator into chat_channel_members with role = 'admin'
  3. Insert each memberIds entry with role = 'member'
  Returns new channel object.

FUNCTION: markChannelRead(channelId)
  supabase
    .from('chat_channel_members')
    .update({ last_read_at: new Date().toISOString() })
    .eq('channel_id', channelId)
    .eq('user_id', currentUser.id)

STEP 3 — SUPABASE REALTIME SUBSCRIPTION
--------------------------------------------------------------------------------

On channel select:
  1. Unsubscribe from previous channel subscription (if any).
  2. Subscribe to new channel:

  const subscription = supabase
    .channel(`chat:${channelId}`)
    .on(
      'postgres_changes',
      { event: 'INSERT', schema: 'public', table: 'chat_messages',
        filter: `channel_id=eq.${channelId}` },
      payload => appendMessage(payload.new)
    )
    .on(
      'postgres_changes',
      { event: 'UPDATE', schema: 'public', table: 'chat_messages',
        filter: `channel_id=eq.${channelId}` },
      payload => updateMessage(payload.new)
    )
    .on(
      'postgres_changes',
      { event: '*', schema: 'public', table: 'chat_message_reactions',
        filter: `message_id=eq.${channelId}` },  -- broadcast all reaction changes
      payload => updateReactions(payload)
    )
    .subscribe()

  Store subscription ref; call subscription.unsubscribe() on channel change or component unmount.

Typing Indicator via Presence:
  const presenceChannel = supabase.channel(`presence:${channelId}`)
  presenceChannel
    .on('presence', { event: 'sync' }, () => {
      const state = presenceChannel.presenceState()
      setTypingUsers(Object.values(state).flat().filter(u => u.isTyping))
    })
    .subscribe(async status => {
      if (status === 'SUBSCRIBED') {
        await presenceChannel.track({ user_id: currentUser.id, name: currentUser.name, isTyping: false })
      }
    })

  On keypress: presenceChannel.track({ ...currentUser, isTyping: true })
  On 3s inactivity timeout: presenceChannel.track({ ...currentUser, isTyping: false })

STEP 4 — FILE STORAGE (Replace FileSharingService)
--------------------------------------------------------------------------------

Bucket configuration:
  Name     : chat-files
  Access   : Private (no public access)
  RLS      : Channel members can read files whose path starts with their channel_id.

Upload flow:
  1. User drags file or clicks [Attach].
  2. Validate size (max 25MB) and type (no .exe/.bat/.sh/.ps1).
  3. Show upload progress bar in message input area.
  4. Upload binary:
       const path = `${channelId}/${messageId}_${sanitizedFilename}`
       supabase.storage.from('chat-files').upload(path, file, { upsert: false })
  5. On upload success: insert row into chat_message_attachments with file_url = path.
  6. For images: generate thumbnail via canvas API before upload; store thumbnail_url.

Download / display:
  Get signed URL (expires 1 hour):
    const { data } = supabase.storage.from('chat-files').createSignedUrl(path, 3600)

  Images: render <img src={signedUrl}> inline in message (max-width 400px, click to open full).
  Other files: render file chip (icon + name + size + Download link using signed URL).

  Signed URLs are re-generated on page load / when they expire; do not persist signed URLs to DB.

STEP 5 — ONLINE PRESENCE
--------------------------------------------------------------------------------

On login / app mount:
  supabase.from('user_presence').upsert({
    user_id: currentUser.id,
    status: 'online',
    last_seen_at: new Date().toISOString()
  }, { onConflict: 'user_id' })

Heartbeat (every 30 seconds):
  setInterval(() => {
    supabase.from('user_presence').update({
      last_seen_at: new Date().toISOString()
    }).eq('user_id', currentUser.id)
  }, 30000)

On tab blur (visibilitychange event, document.hidden = true):
  Update status = 'away'

On tab focus return:
  Update status = 'online'

On unload (beforeunload):
  Update status = 'offline'
  Note: use navigator.sendBeacon for reliability on tab close.

Subscribe to presence for current channel members:
  supabase
    .channel('user-presence-global')
    .on('postgres_changes',
      { event: '*', schema: 'public', table: 'user_presence' },
      payload => updatePresenceState(payload.new)
    )
    .subscribe()

  This updates the sidebar green/gray dots in real time.

Derived offline rule: if last_seen_at < now() - 90s AND status != 'offline', treat as offline
(handles cases where browser crashes without firing beforeunload).

2.1 CHANNEL MANAGEMENT
--------------------------------------------------------------------------------

Channel Types:

  dm        — exactly 2 users; auto-created; name = other user's name

Channel Categories (sidebar grouping, HR defaults):
  Teams     — department/team channels
  Projects  — project-specific channels

Browse All Channels:

2.6 READ RECEIPTS & UNREAD COUNTS
--------------------------------------------------------------------------------

Tracking:
  chat_channel_members.last_read_at updated via markChannelRead(channelId) when:
    - User opens/focuses a channel
    - User scrolls to the bottom of a channel's message list

Unread Count:
  COUNT(chat_messages) WHERE channel_id = X AND created_at > last_read_at AND sender_id != currentUser.id
  Displayed as badge in sidebar (max "99+")

New Messages Divider:
  When opening a channel with unread messages, a "─── New Messages ───" divider
  is inserted between the last-read message and the first unread message
  Scroll position jumps to this divider
  Divider disappears after user scrolls past it (mark-read fires)

Per-channel Notification Preference:
  All Messages  — sidebar badge + push notification for every message
  Mentions Only — sidebar badge + push notification for @mentions only (default for public channels)
  Nothing (Mute) — no badge, no push; channel grayed out in sidebar with 🔇 icon
  DM channels: cannot be muted (notification preference locked to "all")

Notification Snooze:
  User can snooze all notifications for 30min / 1hr / 2hr / until tomorrow
  During snooze: no push notifications delivered for any channel

SECTION 3 — DATA MODEL
================================================================================

  See Step 1 (Section 1) for complete table definitions.

Key relationships:
  chat_channels  1──* chat_channel_members
  chat_channels  1──* chat_messages
  chat_messages  1──* chat_message_reactions
  chat_messages  1──* chat_message_attachments
  chat_messages  *──1 chat_messages (self-ref: parent_message_id)
  app_users      1──1 user_presence

Row Level Security (RLS) — key policies:
  chat_messages:    SELECT/INSERT if user is member of channel_id
  chat_channel_members: SELECT if user is member of same channel; INSERT only for admins
  chat_message_reactions: SELECT/INSERT/DELETE if user is member of the message's channel
  chat_message_attachments: SELECT if user is member of the attachment's message's channel
  user_presence:   SELECT for all authenticated users; UPDATE only own row


================================================================================
SECTION 4 — VALIDATION RULES
================================================================================

Messages:
  - Max length: 4,000 characters
  - Cannot be empty or whitespace-only (trim before insert)
  - Cannot send message to archived channel
  - Cannot send message to channel user is not a member of

Channel Name:
  - Min 3 characters, max 80 characters
  - Allowed characters: lowercase a-z, 0-9, hyphen (-), underscore (_)
  - No spaces (UI auto-converts spaces to hyphens on input)
  - Must be unique within the organisation (case-insensitive)
  - Cannot match an existing category name

File Uploads:
  - Max size: 25 MB per file
  - Blocked extensions: .exe .bat .sh .ps1 .cmd .com .vbs .msi .dmg .app
  - Client-side validation before upload attempt
  - Server-side mime-type validation in Supabase Storage bucket policy

Channel Deletion:
  - Cannot hard-delete a channel that has messages (use Archive instead)
  - Empty channels (no messages) can be deleted permanently by admin

DM Constraints:
  - Cannot create DM with deactivated or deleted user
  - Cannot create DM with yourself

Thread Depth:
  - Maximum 1 level: can reply to root messages only
  - Replies cannot be replied to (reply button hidden on threaded messages)
  - Enforced by: insert validation checks parent_message_id has no parent of its own

Edit / Delete Window:
  - Members: can edit/delete own messages within 24 hours of creation
  - Admins: can delete any message at any time (no edit window for others' messages)
  - Enforced client-side (hide buttons) AND server-side (RLS policy on updated_at check)

Reaction:
  - One instance of each emoji per user per message (UNIQUE constraint)
  - Max distinct reaction types per message: 20 (UI hides overflow behind [+n more])

Members:
  - Min 1 admin per channel at all times (last admin cannot demote self or leave)
  - DM channels: exactly 2 members; cannot add or remove
  - Group DM: 3–8 members; can add up to max; cannot remove members

Circular Category:
  - Cannot name a category the same as an existing channel name

SECTION 6 — PUSH NOTIFICATIONS

Notification Events and Delivery:

  dm_received
    Recipient  : DM recipient
    Web push   : Always (subject to browser permission and snooze)
    In-app     : Always (unread badge + bell)
    Template   : "New message from {sender}: '{content preview 80 chars}'"

  mention_in_channel
    Recipient  : Mentioned user (@name)
    Web push   : Always (even if channel notification pref = Mentions Only or Nothing)
    In-app     : Always (unread badge + bell)
    Template   : "{sender} mentioned you in #{channel}: '{content preview}'"

  channel_invite
    Recipient  : Newly added member
    Web push   : Always
    In-app     : Always
    Template   : "You were added to #{channel} by {inviter}"

  new_message_in_channel
    Recipient  : Channel members (excluding sender)
    Web push   : Only if notification_preference = 'all'
    In-app     : Unread badge only (no bell entry unless also a mention)
    Template   : "{sender} in #{channel}: '{content preview}'"

  thread_reply_own_message
    Recipient  : Author of the parent message
    Web push   : No
    In-app     : Yes (bell entry)
    Template   : "{sender} replied to your message in #{channel}"

  file_shared
    Recipient  : Channel members
    Web push   : No
    In-app     : No bell entry (only reflected in channel's unread count)
    Template   : "{sender} shared {filename} in #{channel}"

Notification Snooze:
  Options: 30 min | 1 hour | 2 hours | Until tomorrow 8am
  During snooze: web push suppressed for all events; in-app badges still accumulate

Web Push Implementation:
  Uses browser Push API + Service Worker
  Permission requested on first DM received or first @mention
  Stored in user settings; revocable from browser settings
  Notification payload includes: channel_id, message_id for deep-link navigation
