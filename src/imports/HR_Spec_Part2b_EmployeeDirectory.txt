G1 — ORG CHART DRAG-TO-REASSIGN
---------------------------------
Library:
  Use react-d3-tree (or reactflow as alternative). Enable drag events on
  individual tree nodes via onNodeDragStop or equivalent drag-end handler.

Drag Interaction:
  - Only nodes where the logged-in user has permission can show a drag handle.
  - On drag-start: highlight valid drop targets (other managers/nodes).
  - On drag-drop over a target node: pause and show confirmation dialog:

    Body:   "Current manager:  {old_manager_name} ({old_manager_title})"
            "New manager:      {new_manager_name} ({new_manager_title})"
    Buttons: [Cancel] [Confirm Reassignment] (indigo)

    (directly or indirectly) to {employeeName}."
  - This check must also be enforced server-side in the PUT handler.

API Call (on confirm):
  PUT /directory/employees/{id}
  Body: { reports_to: new_manager_id }
  On success: re-fetch org tree; show success toast.
  On error (409 circular): show error toast.

Permission gate:

  Roles granted: Department Manager | HR Admin | HR Manager | Super Admin
  Nodes for users without this permission render without drag handles.

G2 — ACTUAL FILE STORAGE IN SUPABASE STORAGE
----------------------------------------------
Bucket Setup:
  Bucket name: employee-documents
  Access type: Private (not public)
  RLS policies:
    - Employee can read own documents:
        USING (auth.uid() = (SELECT user_id FROM employees WHERE id = employee_id))
    - HR Admin / HR Manager / Super Admin can read all:
        USING (has_role(auth.uid(), ARRAY['hr_admin','hr_manager','super_admin']))
    - Uploader roles can insert:
        WITH CHECK (has_role(auth.uid(), ARRAY['hr_admin','hr_manager','super_admin','employee']))

Upload Flow (React):
  const { data, error } = await supabase.storage
    .from('employee-documents')
    .upload(
      `${employeeId}/${docType}_${Date.now()}.${ext}`,
      file,
      { upsert: false, contentType: file.type }
    );

  if (error) throw error;

  const { data: urlData } = supabase.storage
    .from('employee-documents')
    .getPublicUrl(data.path);   // returns signed URL for private bucket

  // Store in employee_documents table:
  await supabase.from('employee_documents').insert({
    employee_id:   employeeId,
    doc_type:      docType,
    file_name:     file.name,
    file_url:      urlData.publicUrl,
    file_size:     file.size,
    uploaded_by:   currentUserId,
    uploaded_at:   new Date().toISOString(),
    expiry_date:   expiryDate ?? null
  });

Max file size: 10 MB per document (enforce client-side and via Supabase bucket policy).
Allowed MIME types: application/pdf | image/jpeg | image/png | image/webp

Preview behaviour:
  - PDF:   embed in <iframe> inside a modal (height: 80vh)
  - Image: display inline in <img> inside a modal (object-fit: contain)
  - Other: show [Download] link — no inline preview

Replace existing metadata-only approach: remove any placeholder file_url logic
and always populate file_url from the storage upload response.

G6 — ON-LEAVE AND WFH BADGES
------------------------------
Data source: Cross-reference with the leaves table at list/card load time.

Query logic:
  SELECT employee_id FROM leaves
  WHERE status = 'approved'
    AND start_date <= CURRENT_DATE
    AND end_date >= CURRENT_DATE
    AND leave_type != 'WFH';

  SELECT employee_id FROM leaves
  WHERE status = 'approved'
    AND start_date = CURRENT_DATE
    AND leave_type = 'WFH';

Rendering:
  - On Leave: amber chip "On Leave" — shown on both card view and list row.
  - WFH Today: blue chip "WFH Today" — shown on both card view and list row.
  - Both chips can appear simultaneously (e.g., partial day).

Update frequency: re-query on page load and once per hour (stale-while-revalidate).

G7 — BIRTHDAY AND WORK ANNIVERSARY BADGES
-------------------------------------------
Birthday logic (client-side, computed from date_of_birth):
  - Today: month === today.month && day === today.day
    → Show pink chip: "Birthday Today!" on card and row
  - This week: birthday falls within the next 7 calendar days
    → Show muted pink chip: "Birthday This Week"

Anniversary logic (computed from join_date):
  - Today: month === today.month && day === today.day
    → Compute years = today.year - join_date.year
    → Show gold chip: "{N} Year{s} Today!" on card and row
  - This week: anniversary falls within the next 7 calendar days
    → Show muted gold chip: "Anniversary This Week"

Rendering notes:
  - Chips rendered after leave badges in visual stacking order.
  - "Today" variants use filled chip; "This Week" variants use outline chip.
  - Computed entirely client-side — no additional API call required.

AUTO-GENERATION of employee_code:
  CREATE OR REPLACE FUNCTION generate_employee_code()
  RETURNS TRIGGER AS $$
  DECLARE
    seq INT;
  BEGIN
    SELECT COUNT(*) + 1 INTO seq
    FROM employees
    WHERE EXTRACT(YEAR FROM created_at) = EXTRACT(YEAR FROM now());

    NEW.employee_code := 'EMP-' || TO_CHAR(now(), 'YYYY') || '-' ||
                         LPAD(seq::TEXT, 4, '0');
    RETURN NEW;
  END;
  $$ LANGUAGE plpgsql;

  CREATE TRIGGER trg_employee_code
  BEFORE INSERT ON employees
  FOR EACH ROW
  WHEN (NEW.employee_code IS NULL)
  EXECUTE FUNCTION generate_employee_code();

SECTION 4 — VALIDATION RULES
================================================================================

Employee Code:
  - Auto-generated on INSERT via DB trigger; format EMP-{YYYY}-{0001}.
  - Immutable after creation (UI hides field; API rejects updates to this field).
  - Uniqueness enforced at DB level (UNIQUE constraint).

Work Email:
  - Unique constraint in DB.
  - Must match corporate domain (configurable regex in Master Data config).
  - Cannot be the same as personal_email for the same employee.
  - Client-side validation + DB unique constraint.

Date of Birth:
  - Age must be >= 18 years and <= 75 years at time of entry.
  - Validation: age = today - date_of_birth; reject if outside range.
  - Client-side + server-side (Edge Function or CHECK constraint).

Join Date:
  - Cannot be more than 90 days in the future from today.
  - Cannot be before 1970-01-01 (sanity check).

Reports To (Manager field):
  - Circular hierarchy check (client-side pre-validation + server-side):
      Walk upward from new_manager_id; if employee.id appears → reject.
  - Employee cannot be their own manager (reports_to != id).
  - DB: no FK circular check built-in; enforce via server-side logic.

PAN Number:
  - Regex: /^[A-Z]{5}[0-9]{4}[A-Z]{1}$/
  - Stored encrypted (AES-256 or Supabase Vault).
  - Displayed as masked: "ABCDE****F" (last char visible, middle digits hidden).

Document Expiry Alerts:
  - 60-day warning:  auto-flagged in compliance view; notification queued.
  - 30-day warning:  alert-level flag; web push notification sent to HR Admin.
  - On expiry date:  status = Expired; urgent web push; critical flag in UI.
  - Implemented via a scheduled Supabase Edge Function (daily cron at 08:00 local).

Bulk CSV Import:
  - Max 500 rows per upload.
  - Mandatory fields validated row by row:
      first_name | last_name | work_email | department | designation | join_date
  - Duplicate email detection: skip row, record as skipped (show which rows).
  - Date columns: accept DD-MMM-YYYY, DD/MM/YYYY, YYYY-MM-DD; normalise to ISO.
  - Show preview modal (first 10 rows) before final import.
  - Import result summary: "{N} created | {M} skipped (duplicates) | {E} errors"
  - Errors shown per row with specific field-level messages.
  - Progress bar for uploads > 50 rows.

Profile Deactivation/Delete:
  - Hard delete blocked if employee has:
      - Active leaves (approved, start_date >= today)
      - Open tasks or projects (cross-check via Project Management module)
      - Pending expense claims
  - Show blocking reasons dialog; offer [Deactivate Instead] as safe alternative.
  - Deactivation: sets status = 'Inactive', records deactivated_at timestamp.
  - Soft-delete only: add deleted_at TIMESTAMPTZ; filter deleted_at IS NULL everywhere.

SECTION 5 — CROSS-APP INTEGRATIONS
================================================================================

RECRUITMENT / ONBOARDING → DIRECTORY
  Trigger:  Onboarding checklist marked complete for a new hire.
  Action:   POST /directory/employees with pre-filled data from offer/onboarding.
  Result:   Employee record created automatically; no manual HR entry needed.
  Fields:   first_name, last_name, work_email, department, designation,
            join_date, reports_to populated from onboarding record.

PERFORMANCE → DIRECTORY
  Trigger:  Performance review cycle finalized (status = 'closed').
  Action:   PATCH /directory/employees/{id}
            Body: { final_rating, competency_scores, last_review_cycle_id }
  Result:   Directory displays latest rating; read-only in Directory UI.

TRAINING → DIRECTORY
  Trigger:  Employee completes a training course and earns a certificate.
  Action:   POST /directory/employee-certifications
            Body: { employee_id, name, issuer, issue_date, expiry_date,
                    credential_id, file_url }
  Result:   Certificate appears in employee's Certifications section in drawer.

DIRECTORY → USER MANAGEMENT
  Trigger:  Employee status changed to 'Inactive' or 'Exit Process'.
  Action:   PATCH /user-management/users/{user_id}
            Body: { status: 'suspended', suspended_at: now(), suspended_reason: 'Employment ended' }
  Result:   User loses login access immediately; IT notified via push notification.

  Trigger:  Employee name / department / designation updated.
  Action:   PUT /user-management/users/{user_id}
            Body: { display_name, department, designation }
  Result:   User profile in all apps stays in sync.

DIRECTORY → COLLABORATION HUB
  Trigger:  New employee record created.
  Action:   POST /collaboration/channel-members
            Body: { channel: 'general', user_id }
            POST /collaboration/channel-members
            Body: { channel: department_channel_id, user_id }
  Result:   New employee auto-added to General + their department channel.

DIRECTORY → EMPLOYEE DASHBOARD
  Direction: Dashboard reads from Directory.
  Data:     On-leave status, WFH status for the logged-in employee.
  Method:   Shared Supabase query (leaves table cross-ref); no separate API call.

DIRECTORY → ALL APPS (name/dept sync)
  Mechanism: Supabase DB trigger on employees table UPDATE watches:
               first_name, last_name, department_id, designation_id
             On change: calls User Management sync endpoint (as above).
  Ensures:  Display names and department info consistent across all modules.

  Trigger:    Daily cron at 08:00; query employees where
              DATE_PART('month', date_of_birth) = current month AND
              DATE_PART('day',   date_of_birth) = current day

work_anniversary
  Recipient:  Employee's direct manager
  Message:    "{firstName} {lastName} is completing {N} year(s) with us today!"
  Type:       info
  Channel:    In-app notification only
  Trigger:    Daily cron at 08:00; compute years from join_date

document_expiry_30d
  Recipient:  All HR Admin users
  Message:    "{firstName} {lastName}'s {doc_type_label} expires on
               {expiry_date_formatted} — please arrange renewal."
  Type:       warning
  Channel:    Web Push + In-app
  Trigger:    Daily cron; query employee_documents where
              expiry_date = today + 30 AND is_active = true

document_expired
  Recipient:  All HR Admin users
  Message:    "{firstName} {lastName}'s {doc_type_label} has expired as of {date}."
  Type:       urgent_warning
  Channel:    Web Push + In-app
  Trigger:    Daily cron; query employee_documents where
              expiry_date < today AND status != 'Expired' AND is_active = true

profile_updated_by_hr
  Recipient:  The employee whose profile was changed
  Message:    "Your profile was updated by {changer_name} on {date}."
  Type:       info
  Channel:    In-app only
  Trigger:    Fired on each write to employee_audit_log where
              changed_by != employee.user_id (i.e., HR/Admin changed it)

bulk_import_completed
  Recipient:  The admin user who initiated the import
  Message:    "CSV import complete: {success} employees created,
               {skipped} skipped (duplicates), {errors} errors."
  Type:       info
  Channel:    In-app only
  Trigger:    On completion of bulk import Edge Function

employee_deactivated
  Recipient:  IT Admin role users
  Message:    "{firstName} {lastName}'s account has been deactivated.
               Please revoke system access and collect physical assets."
  Type:       action_required
  Channel:    Web Push + In-app
  Trigger:    On UPDATE employees SET status = 'Inactive' or 'Exit Process'

Notification Payload Structure (Web Push API):
  {
    "title":   "{notification_title}",
    "body":    "{message}",
    "icon":    "/icons/hr-suite-192.png",
    "badge":   "/icons/badge-72.png",
    "tag":     "{event_type}_{entity_id}",
    "data": {
      "url":   "/{app_path}?employee={employee_id}",
      "type":  "{info|warning|urgent_warning|action_required}"
    }
  }
