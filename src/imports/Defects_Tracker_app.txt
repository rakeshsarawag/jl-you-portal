Defect Tracker — Standalone App Specification
APP OVERVIEW
Purpose: Cross-project defect visibility and SLA-driven resolution tracking. All defects from the Projects app are available here in a unified view. Defects are still created and owned in Projects but tracked, escalated, and reported from this app.

Sync model: Bidirectional real-time sync — changes in either app reflect immediately in both.

VALIDATION & SLA RULES

SLA RULES:
- SLA clock starts on defect creation (not assignment)
- Three SLA milestones per defect:
    1. First Response SLA  — assignee must acknowledge (add comment or change status)
    2. Fix SLA             — status must reach "Fixed"
    3. Verification SLA    — status must reach "Verified" after Fixed
- Pause SLA when: status = Deferred | Won't Fix | Waiting for Info
- Resume SLA when: status moves back to Open/In Progress
- Once breached: cannot un-breach (historical record)
- S1 unassigned > 30 min: auto-escalate to team lead + manager
- S1/S2 unassigned > 1h: page on-call via notification

STATUS TRANSITIONS (enforce in UI):
  Open         → In Progress | Deferred | Won't Fix | Duplicate
  In Progress  → Fixed | Blocked | Open (revert)
  Blocked      → In Progress | Won't Fix
  Fixed        → Verified | In Progress (failed verification = regression)
  Verified     → Closed
  Deferred     → Open (re-activate)
  Won't Fix    → Open (re-evaluate)
  Duplicate    → (terminal — link to original defect required)
  Closed       → Open (regression — must enter reason, auto-sets regression=true)

SEVERITY CHANGE RULES:
  - Upgrade to S1: requires manager approval OR linked production incident ticket
  - Downgrade from S1: requires team lead approval + reason
  - All severity changes logged in activity history

FIX RULES:
  - Cannot move to Fixed without: Fix Description (min 30 chars) + Fix Version
  - Cannot move to Verified without: Verified By user + Test Evidence (comment/attachment)
  - Regression rule: if defect Closed → reopened, regression flag auto-set = true, severity auto-suggest +1 level

DUPLICATE RULE:
  - Marking as Duplicate requires linking to the original defect (mandatory)
  - Original defect gets a "X duplicates" badge

REJECTION RULE:
  - Won't Fix requires: reason from DEFECT_REJECTION_REASONS + approver
  - Reporter is notified with reason

INTEGRATION WITH PROJECTS APP

SYNC RULES:
  1. Every defect created in Projects app auto-appears in Defect Tracker
  2. Every defect created in Defect Tracker auto-appears in its project's Defects tab
  3. Status changes sync bidirectionally in real-time (websocket or polling 30s)
  4. Comments sync — comment in either app appears in both
  5. SLA is owned and calculated by Defect Tracker (Projects app reads it)
  6. Assignment in either app → syncs to both

NAVIGATION:
  - Projects App Defect row → "Open in Defect Tracker ↗" deep link
  - Defect Tracker row → "Open in [ProjectName] ↗" link → navigates to Projects app
  - Defect Tracker breadcrumb shows project → click → opens Projects app detail

WHAT DEFECT TRACKER ADDS THAT PROJECTS APP DOESN'T HAVE:
  - Cross-project view (all defects from all projects in one screen)
  - Defect SLA management (separate from ticket SLA)
  - SLA Tracker screen
  - Root cause analytics across projects
  - Regression trend analysis
  - Defect aging reports
  - Saved cross-project filters
  - S1 alert panel with escalation workflow

SHARED DATA:
  - Users and teams (single source)
  - Notifications (single queue, badge on both apps)
  - Files/attachments (shared storage)
  - Activity logs (shared, show in both apps)

Severity escalated	Assignee + Reporter + PM	"DEF-{id} severity changed to {new} by {actor}"
