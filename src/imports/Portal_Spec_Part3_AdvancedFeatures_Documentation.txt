CREATE TABLE: custom_reports
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid()
  name                  TEXT NOT NULL CHECK (length(name) BETWEEN 3 AND 100)
  description           TEXT
  type                  TEXT NOT NULL CHECK (type IN ('table', 'chart', 'dashboard'))

  metric_config         JSONB NOT NULL DEFAULT '{}'
  filter_config         JSONB NOT NULL DEFAULT '{}'
  is_favorite           BOOLEAN NOT NULL DEFAULT false
  schedule              TEXT CHECK (schedule IN (NULL, 'daily', 'weekly', 'monthly', 'custom'))
  schedule_time         TEXT  -- e.g. '08:00'
  schedule_cron         TEXT  -- for custom schedule, e.g. '0 8 * * 1'
  schedule_recipients   TEXT[] NOT NULL DEFAULT '{}'
  last_run_at           TIMESTAMPTZ
  last_run_output       JSONB  -- { columns: [...], rows: [...], row_count: N }
  run_count             INTEGER NOT NULL DEFAULT 0
  created_by            UUID NOT NULL REFERENCES auth.users(id)
  created_at            TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT now()

MIGRATION STEPS:
  Step 1: Create custom_reports table and report_runs table (see Data Model section).
  Step 2: Expose REST endpoints:
    GET  /api/custom-reports?user_id=         -> returns user's reports
    POST /api/custom-reports                  -> creates new report
    PUT  /api/custom-reports/{id}             -> updates report
    DEL  /api/custom-reports/{id}             -> deletes report
    POST /api/custom-reports/{id}/run         -> server-side execution, returns row data
  Step 3: Replace ReportingService.getReports() with GET /api/custom-reports?user_id=
  Step 4: Replace ReportingService.createReport() with POST /api/custom-reports
  Step 5: Replace ReportingService.runReport(id) with POST /api/custom-reports/{id}/run
  Step 6: On POST /{id}/run — server queries the report's domain API using filter_config,
          returns { columns, rows, run_at, row_count } and stores in last_run_output (max 1000 rows)
  Step 7: Migrate any existing localStorage reports to DB on first user login
          (check localStorage key 'custom_reports', POST each to API, then clear localStorage)

Replace all static/hardcoded monitoring data with real metrics.

METRICS TO COLLECT:
  - API Response Time (ms): logged by each Edge Function into monitoring_metrics on every invocation
  - Error Rate (%): count HTTP 5xx responses in monitoring_metrics in last 60 minutes
  - Active Users (count): count Supabase auth sessions active in last 15 minutes
  - Database Connections (count): pg_stat_activity count — visible to admin role only
  - Memory Usage (% or MB): if hosted on VPS/dedicated server, returned by /api/server-metrics;
    for Supabase-hosted deployments, show Supabase project quota usage from Supabase Management API
  - Storage Usage (GB): Supabase Storage bucket total usage

METRIC COLLECTION:
  - Each Supabase Edge Function logs its own response time at the end of execution:
      INSERT INTO monitoring_metrics (metric_name, value, unit, status, timestamp)
      VALUES ('api_response_time', <ms>, 'ms', <derived_status>, now())
  - A separate health-check Edge Function runs every 60 seconds (scheduled):
      Collects: active users, DB connections, storage usage
      Inserts a batch of rows into monitoring_metrics

THRESHOLDS (configurable in Master Data: MONITORING_THRESHOLDS):
  API Response Time:  warning > 500ms    critical > 2000ms
  Error Rate:         warning > 1%       critical > 5%
  Active Users:       informational only (no threshold)
  DB Connections:     warning > 80       critical > 100
  Memory Usage:       warning > 70%      critical > 90%
  Storage Usage:      warning > 80%      critical > 95%

STATUS DERIVATION:
  healthy  = below warning threshold
  warning  = at or above warning, below critical
  critical = at or above critical threshold

UI BEHAVIOR:
  Auto-refresh: polling every 60 seconds (not Realtime; polling is correct for monitoring)
  Display: countdown "Refreshing in 45s" shown in top-right of Monitoring tab
  Manual refresh: [Refresh Now] button resets countdown and immediately re-fetches
  Each metric shows: current value, status badge (green/yellow/red), sparkline of last 24 readings
  Gauge style: semi-circle gauge with needle, colored by status
  Recent Events log: last 50 monitoring_metrics rows, columns: Timestamp | Metric | Value | Status | Details link

--- 2C. REPORT BUILDER — PROPER EXECUTION (Fix G6, G7) ---

REPORT RUN FLOW:
  1. User clicks [Run] on a report card
  2. POST /api/custom-reports/{id}/run
  3. Server-side Edge Function:
     a. Loads report's domain + filter_config + metric_config
     b. Queries the appropriate domain API (e.g., HR API for employee metrics)
     c. Applies filters from filter_config
     d. Returns: { columns: [...], rows: [...], run_at: ISO, row_count: N }
     e. Stores result in custom_reports.last_run_output (truncated to 1000 rows max)
     f. Inserts row into report_runs table
     g. Updates custom_reports.last_run_at and run_count
  4. Client receives result, displays DataTable inline below the report card
  5. Push notification (in-app): "report_ready" -> report creator

  Excel: SheetJS (xlsx library) binary format; each column typed correctly (numbers as numbers)
  PDF:   open browser print dialog scoped to the data table div (CSS @media print), or
         POST /api/custom-reports/{id}/export?format=pdf -> puppeteer-generated PDF -> download URL

DATA TABLE DISPLAY:

--- 2E. SMART SEARCH (New Feature — previously a no-op hero card) ---

ENTRY POINT:
  Global search bar in Advanced Features hero section
  Keyboard shortcut: Cmd+K (Mac) / Ctrl+K (Windows) -> opens search modal from ANY app in the portal

SEARCH SCOPE (queries across all app entities):
  - employees         (HR app)
  - tasks             (Task Management app)
  - projects          (Project Management app)
  - defects           (Defect Tracking app)
  - invoices          (Finance app)
  - IT tickets        (IT Service Management app)
  - training courses  (Training app)
  - announcements     (Communications app)
  - documents         (Document Management app)

IMPLEMENTATION:
  Full-text search using Supabase pg_tsvector columns on each key table
  Each table has: ALTER TABLE <table> ADD COLUMN search_vector tsvector GENERATED ALWAYS AS (...) STORED;
  Supabase Edge Function: POST /api/search { query: string, scopes?: string[] }
    -> parallel queries across all scoped tables using to_tsquery()
    -> returns { results: [ { entity_type, id, title, preview, route, score } ] }
    -> sorted by rank (ts_rank) within each entity type group

RESULTS UI:
  Grouped by entity type: "Employees (3)", "IT Tickets (2)", "Training Courses (5)"
  Each result: icon chip + title bold + 1-line preview text
  Click result: navigate to entity in source app (uses route from search result)
  No results: "No results for '{query}'" with suggested corrections

RATE LIMIT:
  10 requests per minute per user (enforced in Edge Function via sliding window in Redis or Supabase KV)
  Min query length: 3 characters (enforced client-side and server-side)

3. DATA MODEL

TABLE: custom_reports
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid()
  name                  TEXT NOT NULL CHECK (length(name) BETWEEN 3 AND 100)
  description           TEXT
  type                  TEXT NOT NULL CHECK (type IN ('table', 'chart', 'dashboard'))
  domain                TEXT NOT NULL
  metric_config         JSONB NOT NULL DEFAULT '{}'
  filter_config         JSONB NOT NULL DEFAULT '{}'
  is_favorite           BOOLEAN NOT NULL DEFAULT false
  schedule              TEXT CHECK (schedule IN ('daily', 'weekly', 'monthly', 'custom'))
  schedule_time         TEXT
  schedule_cron         TEXT
  schedule_recipients   TEXT[] NOT NULL DEFAULT '{}'
  next_run_at           TIMESTAMPTZ
  last_run_at           TIMESTAMPTZ
  last_run_output       JSONB
  run_count             INTEGER NOT NULL DEFAULT 0
  created_by            UUID NOT NULL REFERENCES auth.users(id)
  created_at            TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT now()

  CONSTRAINTS:
    UNIQUE (name, created_by)  -- report names unique per user

TABLE: report_runs
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid()
  report_id             UUID NOT NULL REFERENCES custom_reports(id) ON DELETE CASCADE
  run_at                TIMESTAMPTZ NOT NULL DEFAULT now()
  run_by                UUID REFERENCES auth.users(id)  -- NULL if scheduled
  trigger               TEXT NOT NULL CHECK (trigger IN ('manual', 'scheduled'))
  status                TEXT NOT NULL CHECK (status IN ('running', 'success', 'error'))
  row_count             INTEGER
  output_url            TEXT  -- for large outputs stored in Supabase Storage
  error_message         TEXT

TABLE: monitoring_metrics
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid()
  metric_name           TEXT NOT NULL  -- e.g. 'api_response_time', 'error_rate', 'active_users'
  value                 NUMERIC NOT NULL
  unit                  TEXT NOT NULL  -- e.g. 'ms', '%', 'count', 'GB'
  status                TEXT NOT NULL CHECK (status IN ('healthy', 'warning', 'critical'))
  source                TEXT  -- e.g. 'edge_function_name', 'health_check', 'server_metrics'
  timestamp             TIMESTAMPTZ NOT NULL DEFAULT now()

  INDEX: (metric_name, timestamp DESC)

TABLE: integrations_config
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid()
  integration_id        TEXT NOT NULL  -- foreign key to INTEGRATIONS master data
  workspace_id          UUID NOT NULL  -- tenant/workspace identifier
  credentials           JSONB  -- encrypted at rest via Supabase Vault; never returned to client
  status                TEXT NOT NULL CHECK (status IN ('connected', 'disconnected', 'error', 'suspended'))
  last_tested_at        TIMESTAMPTZ
  last_synced_at        TIMESTAMPTZ
  config                JSONB NOT NULL DEFAULT '{}'  -- non-sensitive config (channel names, etc.)
  error_message         TEXT
  created_by            UUID NOT NULL REFERENCES auth.users(id)
  created_at            TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT now()

  CONSTRAINTS:
    UNIQUE (integration_id, workspace_id)

TABLE: integration_events
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid()
  integration_id        TEXT NOT NULL
  workspace_id          UUID NOT NULL
  direction             TEXT NOT NULL CHECK (direction IN ('outbound', 'inbound'))
  event_type            TEXT NOT NULL  -- e.g. 'notification_sent', 'calendar_sync', 'test_connection'
  payload_preview       TEXT  -- first 500 chars of payload, secrets redacted
  status                TEXT NOT NULL CHECK (status IN ('success', 'error', 'pending'))
  http_status           INTEGER
  error_message         TEXT
  created_at            TIMESTAMPTZ NOT NULL DEFAULT now()

  INDEX: (integration_id, workspace_id, created_at DESC)
  -- retain only last 1000 events per integration (handled by cleanup cron or trigger)

5. VALIDATION RULES
--------------------------------------------------------------------------------

Report Name:
  - Required
  - Min 3 chars, max 100 chars
  - Must be unique per user (enforced by DB UNIQUE constraint + API 409 response)

Scheduled Report Recipients:
  - At least 1 recipient required if schedule is set
  - Each recipient must be a valid email format (RFC 5322)
  - Max 50 recipients per report

Custom Webhook URL:
  - Must be a valid URL (parseable by URL constructor)
  - Must use HTTPS scheme (no HTTP)
  - Must not resolve to private IP ranges (SSRF protection in Edge Function)

Integration "Test Connection":
  - Must successfully pass before [Save & Connect] is available
  - Test result is time-limited: re-test required if more than 5 minutes since last test

Report Run Output:
  - Max 1000 rows stored in last_run_output JSONB
  - If total rows > 1000: store first 1000 in DB, full dataset written to Supabase Storage as CSV
    and output_url stored in report_runs.output_url
  - Larger datasets require export (CSV/Excel/PDF) to access all rows

Smart Search:
  - Min 3 characters in query (enforced client-side and server-side)
  - Rate limit: 10 requests per minute per user (sliding window)
  - Max 50 results returned per entity type, max 200 total results per query

CREATE TABLE: doc_apps
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid()

  sort_order            INTEGER NOT NULL DEFAULT 0
  is_active             BOOLEAN NOT NULL DEFAULT true
  created_at            TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT now()

CREATE TABLE: doc_sections
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid()
  app_id                UUID NOT NULL REFERENCES doc_apps(id) ON DELETE CASCADE
  section_type          TEXT NOT NULL CHECK (section_type IN ('quickstart', 'feature', 'faq', 'guide', 'video'))
  title                 TEXT NOT NULL
  content               JSONB NOT NULL DEFAULT '{}'  -- rich text as ProseMirror/TipTap JSON
  sort_order            INTEGER NOT NULL DEFAULT 0
  required_role         TEXT  -- NULL = visible to all
  status                TEXT NOT NULL CHECK (status IN ('published', 'draft')) DEFAULT 'draft'
  view_count            INTEGER NOT NULL DEFAULT 0
  is_active             BOOLEAN NOT NULL DEFAULT true
  created_by            UUID REFERENCES auth.users(id)
  created_at            TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT now()

CREATE TABLE: doc_quick_steps
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid()
  app_id                UUID NOT NULL REFERENCES doc_apps(id) ON DELETE CASCADE
  step_number           INTEGER NOT NULL
  title                 TEXT NOT NULL
  description           TEXT NOT NULL
  screenshot_url        TEXT  -- Supabase Storage: doc-images bucket
  is_active             BOOLEAN NOT NULL DEFAULT true
  created_at            TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT now()

  CONSTRAINTS:
    UNIQUE (app_id, step_number)
    CHECK (step_number BETWEEN 1 AND 20)

CREATE TABLE: doc_faqs
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid()
  app_id                UUID NOT NULL REFERENCES doc_apps(id) ON DELETE CASCADE

  question              TEXT NOT NULL CHECK (length(question) >= 10)
  answer                TEXT NOT NULL CHECK (length(answer) >= 20)
  sort_order            INTEGER NOT NULL DEFAULT 0
  status                TEXT NOT NULL CHECK (status IN ('published', 'draft')) DEFAULT 'draft'
  is_active             BOOLEAN NOT NULL DEFAULT true
  created_at            TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT now()

  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid()

  thumbnail_url         TEXT

  sort_order            INTEGER NOT NULL DEFAULT 0

  created_at            TIMESTAMPTZ NOT NULL DEFAULT now()

5. VALIDATION RULES
--------------------------------------------------------------------------------

Quick Steps:
  - Minimum 1 step per app (cannot publish app docs with 0 steps)
  - Maximum 20 steps per app (enforced by DB CHECK constraint)
  - Step title: required, min 3 chars, max 100 chars
  - Screenshot: optional; if provided: max 5MB, PNG/JPEG/WebP only

FAQs:
  - Question: required, min 10 chars, max 500 chars
  - Answer: required, min 20 chars, max 5000 chars
  - category: must be one of: basic, technical, troubleshooting

Videos:
  - URL validation: must match YouTube (youtube.com/watch?v= or youtu.be/) or Vimeo (vimeo.com/) URL patterns
  - Title: required, min 3 chars, max 200 chars
  - Duration: optional; if provided, must be numeric and > 0

Rich Text (Guide Sections):
  - Max 50,000 characters per section (counted from TipTap JSON text nodes)
  - Images within content: same 5MB / PNG/JPEG/WebP rules as screenshots

CMS Edit Authorization:
  - Requires Documentation Admin role (checked server-side on all /api/admin/docs/* endpoints)
  - All admin edits are logged to Security app audit table: { user_id, action, table, row_id, before, after, timestamp }

PDF Generation:
  - Max one PDF generation per app per user per 5 minutes (rate limit to prevent abuse)
  - Edge Function timeout: 30 seconds (increase in Supabase project settings for this function)

Feedback:
  - One vote per user per content item (enforced by UNIQUE constraint)
  - Anonymous voting not permitted (user must be authenticated)
