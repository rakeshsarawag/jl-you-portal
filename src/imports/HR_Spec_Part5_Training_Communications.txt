────────────────────────────────────────────────────────────────────────────────

  TABLE: training_paths
    id               uuid          PRIMARY KEY DEFAULT gen_random_uuid()
    title            text          NOT NULL

    id               uuid          PRIMARY KEY DEFAULT gen_random_uuid()

    enrolled_at      timestamptz   DEFAULT now()
    completed_at     timestamptz
    progress_percent numeric(5,2)  DEFAULT 0

Migration steps:
  1. Run CREATE TABLE migrations above via Supabase SQL editor.
  2. Replace all useState/useReducer learning path state in
     TrainingTrackerEnhanced.tsx with Supabase queries.
  3. On mount: fetch training_paths + training_path_enrollments for current
     employee; subscribe to realtime changes.
  4. All create/edit/delete path operations: call Supabase CRUD, then
     invalidate local query cache.
  5. Path progress recalculated on each training_enrollments completion event
     and written back to training_path_enrollments.progress_percent.

G7 FIX — Certification Expiry and Renewal Tracking
────────────────────────────────────────────────────────────────────────────────

Schema change on training_certificates:
  ALTER TABLE training_certificates
    ADD COLUMN expiry_date         date,
    ADD COLUMN renewal_course_id   uuid REFERENCES training_courses(id),
    ADD COLUMN expiry_status       text
      CHECK (expiry_status IN ('active','expiring_soon','expired'))
      DEFAULT 'active';

Background check (Supabase Edge Function — scheduled via pg_cron or
external cron webhook, runs daily at 07:00 UTC):
  1. SELECT * FROM training_certificates
     WHERE expiry_date IS NOT NULL AND expiry_status != 'expired'.
  2. For each row:
     - If expiry_date - CURRENT_DATE <= 0  → set expiry_status = 'expired';
       push notification: employee URGENT, HR WARNING.
     - If expiry_date - CURRENT_DATE <= 30 → set expiry_status = 'expiring_soon';
       push notification: employee WARNING, manager INFO.
       If renewal_course_id set and no open enrollment exists → auto-create
       enrollment with status = 'not_started'.
     - If expiry_date - CURRENT_DATE <= 90 → flag in compliance report;
       no push (in-app only).
  3. Update compliance report flag in training_certificates.expiry_status.

E.3.1  Learning Paths (Persisted — G1 resolved, expanded feature)
────────────────────────────────────────────────────────────────────────────────

Path definition fields:
  - title (required)
  - description
  - target_role (value help from Master Data: JOB_ROLES)
  - estimated_hours (auto-calculated from sum of course.duration_hours)
  - is_mandatory (boolean toggle)
  - courses: ordered list — drag-and-drop reorder; each course shows:

  - System creates training_path_enrollments row.

[+ Create Path] button: visible only to HR and Trainer roles (Permissions App
check). Opens slide-over form with all path definition fields above.

E.3.2  Skills Gap Analysis (New Tab: Gap Analysis)
────────────────────────────────────────────────────────────────────────────────

Purpose: Compare an employee's current skill levels against role requirements
and surface recommended training to close identified gaps.

Data sources:
  - Employee current skills: from Employee Directory App
    (employee_skills table: employee_id | skill_id | current_level)
  - Role required skills: from Master Data App — COMPETENCY_FRAMEWORKS
    (competency_frameworks: role | skill_id | required_level)
  - Training catalogue: training_courses (skill_category field maps to
    skill_id for recommendation matching)

UI layout:
  - Employee selector (default: logged-in user; managers can select any
    direct report from their team).
  - Header row: "Role: [designation]  |  Skills Framework: [framework_name]"
  - Summary chips: Met (green) | Minor Gap (amber) | Major Gap (red) counts.

Gap analysis table columns:
  Skill | Required Level | Your Level | Gap Status | Recommended Course

  Gap status badge logic:
    - Met:        current_level >= required_level         → green
    - Minor Gap:  required_level - current_level == 1    → amber
    - Major Gap:  required_level - current_level >= 2    → red

  Major Gap rows: red-50 background tint across the row.
  Recommended Course cell: shows matching course name from catalogue (or
  "No course available" in gray if no match); [Enroll] button inline.

Footer actions:
  - [Enroll in All Recommended]: enrolls employee in all courses where
    Gap != 'Met' and a recommended course exists.
  - Manager-only: [Approve & Enroll]: if TRAINING_ENROLLMENT_POLICY
    approval_required = true, manager can approve and trigger enrollment
    from this screen.

Department-wide gap analysis (manager view):
  - Toggle: "Individual / Department View"
  - Department view: aggregated table showing each skill with:
      Skill | Required Level | Avg Team Level | % Employees with Gap
  - Drill-down: click a skill row to see which employees have the gap.

E.3.5  Mandatory Compliance Tracking (Enhanced Compliance Tab)
────────────────────────────────────────────────────────────────────────────────

Per-role mandatory training matrix:
  - Sourced from Master Data App: MANDATORY_TRAINING_MATRIX
    (role | required_course_id | completion_deadline_days_from_joining)
  - Training Tracker reads this matrix to determine which courses are
    mandatory per employee's role.
  - Compliance status per employee: (completed mandatory courses /
    total mandatory courses for role) * 100.

Compliance summary row (top of tab):
  - Org Compliance: X% (green/amber/red based on threshold from Master Data)
  - Overdue: N employees (red if > 0)
  - Due This Month: N employees (amber)

Compliance table columns:
  Employee | Department | Mandatory Courses (total) | Completed | Overdue |
  Status badge | [Send Reminder] button

Status badge logic:
  - Compliant:  all mandatory courses completed            → green
  - At Risk:    1+ courses due within 7 days, not done     → amber
  - Overdue:    1+ courses past due date                   → red

Row expand (click to reveal):
  Per-mandatory-course row: Course Name | Due Date | Completion Date (or "–")
  | Status chip (Completed / Overdue / Not Started)

Escalation engine (Supabase Edge Function, runs daily):
  - Overdue > 7 days:  email to employee
  - Overdue > 14 days: email to employee + direct manager
  - Overdue > 30 days: email to employee + manager + HR VP
  Escalation log stored in a training_escalations table (employee_id |
  course_id | days_overdue | escalation_level | sent_at).

Bulk reminder:
  - Checkbox on each overdue row.
  - [Send Bulk Reminder] button (activates when ≥ 1 row selected).
  - Fires batched notification POST for all selected employees.

Dept filter: filter compliance table by department (value help from
Master Data: DEPARTMENTS).

────────────────────────────────────────────────────────────────────────────────

Policy configuration (Master Data App):
  Key:   TRAINING_ENROLLMENT_POLICY
  Fields:
    approval_required:  boolean
    applies_to:         "non_mandatory"  (only non-mandatory courses)
    approver:           "direct_manager" | "hr"

Enrollment flow when approval_required = true:
  1. Employee clicks [Enroll] on non-mandatory course in catalogue.
  2. System creates training_enrollments row with status = 'pending_approval'.
  3. Push notification sent to approver (manager or HR):
     "Approval Required: [Employee] has requested enrollment in [Course]."
  4. Approver sees pending request in Team tab under "Pending Approvals"

  5. [Approve] → status = 'enrolled'; course card unlocked for employee.
     [Reject] → status = 'rejected'; optional rejection reason text.
  6. Employee notified of approval or rejection via push notification.

Mandatory courses: bypass approval gate entirely; direct enrollment.

E.4  DATA MODEL — TRAINING TRACKER (Full Additions)
════════════════════════════════════════════════════════════════════════════════

  TABLE: training_paths
    id               uuid          PK  DEFAULT gen_random_uuid()
    title            text          NOT NULL
    description      text
    target_role      text
    estimated_hours  numeric(6,2)
    is_mandatory     boolean       DEFAULT false
    status           text          DEFAULT 'draft'
                                   CHECK (status IN ('draft','active','archived'))
    created_by       uuid          REFERENCES auth.users(id)
    created_at       timestamptz   DEFAULT now()

  TABLE: training_path_courses
    id                    uuid   PK  DEFAULT gen_random_uuid()
    path_id               uuid   REFERENCES training_paths(id) ON DELETE CASCADE
    course_id             uuid   REFERENCES training_courses(id)
    order_index           int    NOT NULL
    unlock_after_course_id uuid  REFERENCES training_courses(id)
    UNIQUE (path_id, order_index)

  TABLE: training_path_enrollments
    id               uuid          PK  DEFAULT gen_random_uuid()
    path_id          uuid          REFERENCES training_paths(id)
    employee_id      uuid          REFERENCES auth.users(id)
    enrolled_at      timestamptz   DEFAULT now()
    completed_at     timestamptz
    progress_percent numeric(5,2)  DEFAULT 0
    current_course_id uuid         REFERENCES training_courses(id)
    UNIQUE (path_id, employee_id)

  TABLE: training_sessions
    id               uuid          PK  DEFAULT gen_random_uuid()
    course_id        uuid          REFERENCES training_courses(id)
    title            text          NOT NULL
    session_date     date          NOT NULL
    start_time       time          NOT NULL
    duration_mins    int
    max_attendees    int
    location         text
    meeting_link     text
    trainer_id       uuid          REFERENCES auth.users(id)
    created_at       timestamptz   DEFAULT now()

  TABLE: training_session_registrations
    id               uuid    PK  DEFAULT gen_random_uuid()
    session_id       uuid    REFERENCES training_sessions(id)
    employee_id      uuid    REFERENCES auth.users(id)
    status           text    CHECK (status IN
                             ('registered','waitlisted','attended','no-show'))
                             DEFAULT 'registered'
    registered_at    timestamptz DEFAULT now()
    UNIQUE (session_id, employee_id)

  ALTERED TABLE: training_certificates
    -- existing columns preserved; additions:
    expiry_date          date
    renewal_course_id    uuid    REFERENCES training_courses(id)
    expiry_status        text    DEFAULT 'active'
                                 CHECK (expiry_status IN
                                 ('active','expiring_soon','expired'))

  TABLE: training_needs
    id                    uuid   PK  DEFAULT gen_random_uuid()
    employee_id           uuid   REFERENCES auth.users(id)
    skill_id              uuid   -- references Master Data skill table
    current_level         int    CHECK (current_level BETWEEN 1 AND 5)
    required_level        int    CHECK (required_level BETWEEN 1 AND 5)
    recommended_course_id uuid   REFERENCES training_courses(id)
    status                text   DEFAULT 'identified'
                                 CHECK (status IN
                                 ('identified','enrolled','completed'))
    created_at            timestamptz DEFAULT now()

E.5  VALIDATION RULES — TRAINING TRACKER
════════════════════════════════════════════════════════════════════════════════

Rule 1 — Path Course Unlock:
  Cannot enroll in course N+1 in a path while course N is not status =
  'completed'. Enforced both in UI (button disabled) and at Supabase RLS/
  edge function level before inserting training_enrollments row.

Rule 2 — Mandatory Course Unenrollment:
  Employee cannot unenroll from a mandatory course. The [Unenroll] button is
  hidden when training_enrollments.is_mandatory = true. HR role can override
  with mandatory reason text (audit logged).

Rule 3 — Session Registration Cutoff:
  Cannot register for a session after session_date + start_time has passed.
  [Register] button replaced by "Session has started" label. Enforced at
  UI render time and by CHECK on registration insert (session_date >=
  CURRENT_DATE).

Rule 4 — Waitlist Auto-Promotion:
  When a registered attendee cancels (status set to cancelled):
  SELECT first waitlisted registration (ORDER BY registered_at ASC); update
  to status = 'registered'; send push notification to promoted employee.
  Logic in Supabase database trigger on training_session_registrations.

Rule 5 — Certificate Expiry:
  Cannot set training_certificates.expiry_status = 'active' if expiry_date
  is in the past. Enforced via CHECK constraint:
    CHECK (expiry_status != 'active' OR expiry_date IS NULL
           OR expiry_date >= CURRENT_DATE)
  (Admin override: HR can set expiry_status = 'active' with reason; reason
  stored in expiry_override_reason text column.)

Rule 6 — Learning Path Minimum Courses:
  Cannot save/publish a learning path with fewer than 2 courses. Validated
  at form submit level in the slide-over form component; API also rejects
  paths with < 2 course rows in training_path_courses.

Rule 7 — Progress Cannot Be Manually Set to 100%:
  training_path_enrollments.progress_percent is calculated server-side from
  (completed courses / total courses). Direct client-side writes to 100% are
  rejected unless the final course has status = 'completed'. HR admin can
  override with an audit log entry (admin_override_reason column).

E.13  VALIDATION RULES — COMMUNICATIONS HUB
════════════════════════════════════════════════════════════════════════════════

Rule 1 — Critical Announcement Immutability:
  communications_posts with priority = 'critical' cannot be deleted after
  status = 'published'. [Delete] button hidden for Critical posts once
  published. Archive is the only permitted action (status → 'archived').
  Enforced at API level: DELETE request on a critical published post
  returns 403.

Rule 2 — Scheduled Post Minimum Lead Time:
  scheduled_at must be >= NOW() + 30 minutes. Validated client-side in
  date/time picker (min selectable time = 30 min from now). Also validated
  server-side on INSERT to communications_posts: reject if scheduled_at <
  NOW() + interval '30 minutes'.

Rule 3 — Event Date Integrity:
  For event posts: end_date >= start_date (enforced via CHECK constraint
  and form validation). If max_attendees_enabled = true: max_attendees >= 1.

Rule 4 — RSVP After Event Date:
  Cannot create or update an RSVP row if the event's event_date is in the
  past. CHECK constraint on communications_event_rsvps deferred to
  application layer: on UPSERT, check event.event_date >= CURRENT_DATE;
  return error "Cannot RSVP for past events."

Rule 5 — Recognition Self-Recognition:
  recognition giver_id != receiver_id enforced by:
    CHECK (giver_id != receiver_id) in communications_recognitions table.
  Receiver must be an active employee: validate auth.users.is_active = true
  for receiver_id before insert.

Rule 6 — @Mention Limit:
  Max 10 @mentions per post. Enforced at submit in post composer (count
  mention nodes; disable submit if > 10 with inline error).
  Also enforced server-side: count rows in communications_post_mentions per
  post_id; reject if > 10.

Rule 7 — Post/Announcement Length:
  communications_posts.body content max 5000 characters. Enforced via
  CHECK constraint: char_length(body) <= 5000. Post composer shows live
  character counter (e.g., "4823 / 5000").

Rule 8 — One RSVP Per User Per Event:
  UNIQUE (event_id, user_id) on communications_event_rsvps ensures no
  duplicate RSVPs. Updates (change from Going to Not Going) use
  ON CONFLICT (event_id, user_id) DO UPDATE SET status = excluded.status.
