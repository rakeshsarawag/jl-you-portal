G9 — SLA / DEADLINE ENFORCEMENT ON APPROVAL NODES (Priority: MEDIUM)
──────────────────────────────────────────────────────────────────────
Approval node config panel additions:
  Response Deadline: [24] [hours ▾]  (min: 1 hour, enforced by validation)
  On Timeout:
    (●) Escalate to next level
    ( ) Auto-Approve
    ( ) Auto-Reject

Escalation logic (Escalate to next level):
  1. Look up current approver's employee record in Employee Directory
  2. Follow reports_to chain upward to find next higher-authority user
  3. Create new workflow_approvals row for that user; set escalation_level += 1
  4. Send escalation push notification to new approver
  5. Send info notification to original approver ("escalated due to no response")
  Max escalation levels: 3; if exceeded and still no response, fall back to auto_reject

Supabase CRON Edge Function: check-approval-deadlines
  Schedule: every 60 minutes (cron: 0 * * * *)
  Logic:
    SELECT wa.* FROM workflow_approvals wa
    JOIN workflow_instance_steps wis ON wis.id = wa.step_id
    WHERE wa.status = 'pending'
      AND wa.deadline < NOW()
    For each row:
      - Read approval node config for on_timeout value
      - Execute on_timeout action (escalate | auto_approve | auto_reject)
      - Update workflow_approvals.status accordingly
      - Update workflow_instance_steps.status
      - Fire appropriate push notification (see Section 7)
      - If on_timeout = 'escalate': create new approval row for next-level approver

SECTION 2 — FEATURE SPEC: NEW NODE TYPES
────────────────────────────────────────────────────────────────────────────────

All new nodes are added to the WorkflowBuilder node palette and to the
workflow execution engine.

NODE: delay_node
─────────────────
Display label : "Delay"
Palette icon  : ⏱
Canvas color  : Slate / #64748B
Purpose       : Pause workflow execution for a specified duration before
                proceeding to the next node.

Config fields:
  duration_value  number (required, min 1)
  duration_unit   select: hours | days | weeks
  (Computed display label: "Wait {N} {unit} then continue")

Execution behavior:
  On reaching this node, set step status = 'running', record resume_at timestamp
  (NOW() + duration). The scheduler checks for delayed steps every 15 minutes.
  On resume_at reached: set step status = 'completed', proceed to next node.

────────────────────────────────────────────────────────────────────────────────

NODE: parallel_node
────────────────────
Display label : "Parallel Split"
Palette icon  : ↔
Canvas color  : Violet / #7C3AED
Purpose       : Split workflow into N simultaneous branches; all branches must
                complete before flow continues to the next node after the merge.

Config fields:
  branch_count  number, 2–5 (default 2)
  branch_labels array of strings (e.g. ["Branch A", "Branch B"])
  Each branch contains its own ordered array of child nodes.

Canvas rendering:
  Fan out from the parallel_node into N vertical columns.
  Each branch column has its own node sequence.
  A merge node (implicit, gray diamond) closes all branches back to a single flow.

Execution behavior:
  All branches are instantiated concurrently as sub-steps.
  Overall parallel_node step status = 'running' until ALL branch final steps = 'completed'.
  If any branch fails: parallel_node status = 'failed'; sibling branches are cancelled.
  Branch steps appear as indented rows in the Instance Execution Timeline.

────────────────────────────────────────────────────────────────────────────────

NODE: create_record_node
────────────────────────
Display label : "Create Record"
Palette icon  : 📝
Canvas color  : Emerald / #059669
Purpose       : Create a new record in a target HR app or service.

Config fields:
  target_app    select: all 10 HR apps + IT Services + Training + Projects
  entity        select: filtered by target_app (e.g. IT Services → it_tickets)
  field_mapping array of { source_field: string, target_field: string }
                source_field: from workflow payload or prior node output
                (use dot notation, e.g. "trigger.employee_id")
                target_field: field on the target entity

Output:
  created_record_id (UUID) — available as a variable in subsequent nodes via
  syntax: {{nodes.create_record_1.output.created_record_id}}

Example use cases:
  Create IT provisioning ticket when a new hire is triggered
  Create training enrollment when certification is expiring
  Create onboarding record when candidate_hired event fires

────────────────────────────────────────────────────────────────────────────────

NODE: update_field_node
───────────────────────
Display label : "Update Field"
Palette icon  : ✏️
Canvas color  : Amber / #D97706
Purpose       : Update a single field on an existing record in another app.

Config fields:
  target_app  select (same list as create_record_node)
  entity      select (filtered by app)
  record_id   string — from payload variable (e.g. {{trigger.leave_id}}) or
              prior node output (e.g. {{nodes.create_record_1.output.created_record_id}})
  field       select (field names for target entity)
  new_value   string / dynamic (supports {{variable}} interpolation)

Example use cases:
  Set leave.status = 'approved' after approval node completes
  Set employee.status = 'inactive' on exit workflow
  Set job_posting.status = 'active' after recruitment approval

────────────────────────────────────────────────────────────────────────────────

NODE: email_node
────────────────
Display label : "Send Email"
Palette icon  : 📧
Canvas color  : Sky / #0284C7
Purpose       : Send an email to one or more recipients using a template or
                custom subject/body.

Config fields:
  to              string or array — fixed email address OR dynamic variable
                  (e.g. {{trigger.employee_email}}, {{trigger.manager_email}})
  template        select: from NOTIFICATION_TEMPLATES (optional)
  custom_subject  string with {{variable}} interpolation (overrides template subject)
  custom_body     rich text / markdown with {{variable}} interpolation
  cc              string (optional, supports variables)

Variable interpolation:
  Use {{field_name}} syntax anywhere in subject/body.
  Available variables: all fields from trigger payload + all prior node outputs.
  Builder shows a variable picker panel (click {x} icon in toolbar).

────────────────────────────────────────────────────────────────────────────────

NODE: webhook_node
──────────────────
Display label : "Webhook"
Palette icon  : 🌐
Canvas color  : Rose / #E11D48
Purpose       : Send an HTTP POST request to an external URL.

Config fields:
  url                 string (required, must be https://)
  headers             array of { key: string, value: string }
  body_template       JSON or text with {{variable}} interpolation
  expected_status_code  number (default 200)

Retry policy:
  On failure (non-expected status or network error): retry 3 times
  Retry intervals: 5 minutes | 5 minutes | 5 minutes
  After 3 failures: mark step as 'failed'; trigger workflow_failed notification

Output:
  response_status (number) and response_body (JSONB) available to subsequent nodes.

────────────────────────────────────────────────────────────────────────────────

NODE: loop_node
───────────────
Display label : "Loop"
Palette icon  : 🔄
Canvas color  : Purple / #9333EA
Purpose       : Repeat a sequence of child nodes until an exit condition is met.

Config fields:
  max_iterations  number (default 10, max 50)
  exit_condition  rule-builder object (same format as condition node)
                  evaluated after each loop iteration
  child_nodes     ordered array of nodes to execute per iteration
  loop_delay      number + unit (optional pause between iterations)

Execution behavior:
  Iteration count tracked in step output_payload.
  If exit_condition is true after an iteration: exit loop, proceed to next node.
  If max_iterations reached before condition is true: exit loop with status 'completed'
  (not failed) and add a warning to step output: "Max iterations reached".
  Current iteration number available as {{loop.current_iteration}} inside child nodes.

       Deadline       : 24 hours

       Approver role  : hr_manager
       Deadline       : 48 hours

  6. notification_node — "Notify Employee"

SECTION 4 — DATA MODEL
────────────────────────────────────────────────────────────────────────────────

TABLE: workflow_definitions
  id              UUID         PK  default gen_random_uuid()
  name            TEXT         NOT NULL (unique per org)
  description     TEXT
  trigger_type    TEXT         CHECK IN ('manual','schedule','event')
  trigger_config  JSONB        -- cron/timezone for schedule; app/entity/event_key/condition_filter for event
  nodes           JSONB        -- array of node config objects
  edges           JSONB        -- array of { source_node_id, target_node_id, edge_label } connection objects
  version         INTEGER      NOT NULL DEFAULT 1
  status          TEXT         CHECK IN ('draft','active','paused','archived') DEFAULT 'draft'
  created_by      UUID         FK → auth.users.id
  created_at      TIMESTAMPTZ  DEFAULT NOW()
  updated_at      TIMESTAMPTZ  DEFAULT NOW()
  org_id          UUID         FK → organizations.id

TABLE: workflow_versions
  id              UUID         PK  default gen_random_uuid()
  workflow_id     UUID         FK → workflow_definitions.id ON DELETE CASCADE
  version_number  INTEGER      NOT NULL
  nodes           JSONB        NOT NULL
  edges           JSONB        NOT NULL
  changed_by      UUID         FK → auth.users.id
  changed_at      TIMESTAMPTZ  DEFAULT NOW()
  change_summary  TEXT
  is_current      BOOLEAN      DEFAULT FALSE
  UNIQUE (workflow_id, version_number)

TABLE: workflow_instances
  id                UUID         PK  default gen_random_uuid()
  workflow_id       UUID         FK → workflow_definitions.id
  workflow_version  INTEGER      NOT NULL
  trigger_type      TEXT         CHECK IN ('manual','schedule','event')
  trigger_payload   JSONB
  status            TEXT         CHECK IN ('running','completed','failed','cancelled') DEFAULT 'running'
  started_at        TIMESTAMPTZ  DEFAULT NOW()
  completed_at      TIMESTAMPTZ
  triggered_by      UUID         FK → auth.users.id (NULL for scheduled/event triggers)
  error_message     TEXT

TABLE: workflow_instance_steps
  id              UUID         PK  default gen_random_uuid()
  instance_id     UUID         FK → workflow_instances.id ON DELETE CASCADE
  node_id         TEXT         NOT NULL
  node_type       TEXT         NOT NULL
  node_label      TEXT
  status          TEXT         CHECK IN ('pending','running','completed','failed','skipped') DEFAULT 'pending'
  started_at      TIMESTAMPTZ
  completed_at    TIMESTAMPTZ
  input_payload   JSONB
  output_payload  JSONB
  error_message   TEXT
  INDEX (instance_id, status)

TABLE: workflow_approvals
  id                UUID         PK  default gen_random_uuid()
  instance_id       UUID         FK → workflow_instances.id
  step_id           UUID         FK → workflow_instance_steps.id
  approver_id       UUID         FK → auth.users.id
  status            TEXT         CHECK IN ('pending','approved','rejected','escalated','auto_approved','auto_rejected') DEFAULT 'pending'
  response_at       TIMESTAMPTZ
  response_comment  TEXT
  delegated_to      UUID         FK → auth.users.id (NULL if not delegated)
  deadline          TIMESTAMPTZ  NOT NULL
  escalation_level  INTEGER      DEFAULT 0

TABLE: workflow_trigger_event_mappings
  id               UUID         PK  default gen_random_uuid()
  event_key        TEXT         NOT NULL FK → WORKFLOW_TRIGGER_EVENTS.event_key
  workflow_id      UUID         FK → workflow_definitions.id ON DELETE CASCADE
  is_active        BOOLEAN      DEFAULT TRUE
  condition_filter JSONB        -- optional pre-filter (same format as G5 condition_filter)
  created_by       UUID         FK → auth.users.id
  created_at       TIMESTAMPTZ  DEFAULT NOW()
  UNIQUE (event_key, workflow_id)

Row-Level Security (all tables):
  All reads/writes scoped to org_id.
  workflow_approvals readable by the approver_id and any admin.
  workflow_instance_steps readable by workflow creator, admins, and the original trigger initiator.


────────────────────────────────────────────────────────────────────────────────
SECTION 5 — VALIDATION RULES
────────────────────────────────────────────────────────────────────────────────

WORKFLOW DEFINITION
  - name: required; 3–100 characters; unique per org_id
  - Must have at least 1 trigger node and at least 1 approval or action node to activate
  - Cannot activate a workflow containing disconnected (orphan) nodes — all nodes must be
    reachable from the trigger node via edges
  - Cannot delete a workflow that has instances with status = 'running'
    (must deactivate or archive the workflow first; running instances must complete or be cancelled)
  - Circular trigger guard: if workflow A has an event trigger mapped to workflow B's output,
    and workflow B's trigger is mapped to trigger workflow A, reject the activation with error:
    "Circular trigger detected between Workflow A and Workflow B"
  - status transitions allowed:
      draft → active (via Activate button)
      active → paused (via Pause button)
      paused → active (via Resume button)
      active | paused → archived (via Archive; blocked if running instances exist)

APPROVAL NODES
  - response_deadline_hours: minimum 1, no maximum enforced in UI (business decision)
  - on_timeout: must be one of escalate_to_next_level | auto_approve | auto_reject

PARALLEL NODES
  - branch_count: minimum 2, maximum 5
  - Each branch must contain at least 1 node (cannot have an empty branch)

SCHEDULE TRIGGER
  - Must have a valid cron expression (validated against cron regex on save)
  - Cron must not be more frequent than every 15 minutes
    (first cron field: if numeric, must be divisible by 15 or be */15 or */30)
  - Preset selection automatically fills valid cron; custom cron is validated on blur

EVENT TRIGGER
  - app, entity, and event_key are all required
  - Selected event_key must exist in WORKFLOW_TRIGGER_EVENTS master data

LOOP NODE
  - max_iterations: minimum 1, maximum 50
  - exit_condition is required (must define at least one condition)

WEBHOOK NODE
  - url must start with https:// (HTTP blocked)
  - expected_status_code: 100–599

WORKFLOW VERSION
  - version_number auto-increments; cannot be manually set
  - Only one version per workflow can have is_current = true


────────────────────────────────────────────────────────────────────────────────
SECTION 6 — CROSS-APP INTEGRATIONS
────────────────────────────────────────────────────────────────────────────────

ALL APPS → WORKFLOW AUTOMATION
  Integration point: WORKFLOW_TRIGGER_EVENTS master data
  Any event from any HR module, IT Services, or Projects can trigger a workflow.
  Event firing pattern:
    Each app publishes events via a shared service function: publishEvent(event_key, payload)
    This function inserts into an event_queue table (or calls an Edge Function directly)
    The workflow engine consumes the queue, matches active event mappings, and spawns instances.

WORKFLOW → NOTIFICATION BELL
  On creation of each approval step (workflow_approvals row, status = 'pending'):
    POST to /api/notifications with type = 'action_required'
    recipient_id = approver_id
    message = "Approval required: {workflow_name} — {step_description}"
  Notification Bell queries action_required notifications to populate Pending Approvals count.

WORKFLOW → IT SERVICES
  Via create_record_node with target_app = 'it_services', entity = 'it_tickets'
  Creates a ticket in the IT Services app with mapped fields from workflow payload.
  Returns ticket ID usable in subsequent nodes.

WORKFLOW → TRAINING
  Via create_record_node with target_app = 'training', entity = 'training_enrollments'
  Enrolls an employee in one or more training courses.
  Returns enrollment IDs.

WORKFLOW → COMMUNICATIONS HUB
  Via notification_node with channel_target = 'communications_hub'
  Posts a message to a specified channel or as a general announcement.
  Config: channel_id | message_text | post_as (system | workflow name)

WORKFLOW → COLLABORATION HUB
  Via webhook_node (if Collaboration Hub exposes a webhook endpoint) OR
  via notification_node with channel_target = 'collaboration_hub'
  Posts a message to a team channel.

WORKFLOW → EMPLOYEE DIRECTORY
  Via update_field_node with target_app = 'employee_directory', entity = 'employees'
  Can update fields: employment_status | job_title | department_id | reports_to | location_id
  Write access guarded by permission check: only admin or HR Manager role may update
  employment_status via workflow.

WORKFLOW → USER MANAGEMENT
  Via update_field_node with target_app = 'user_management', entity = 'user_accounts'
  Can update: account_status (active | suspended | deactivated) | roles
  Requires admin-level workflow permission to configure this node type.
  Deactivation is effective-dated (applies on last_working_date via delay_node).

SECTION 7 — PUSH NOTIFICATIONS
────────────────────────────────────────────────────────────────────────────────

All notification events use the shared Notification Service.
Types: web_push | in_app | email
Priority levels: action_required | warning | info | success

EVENT: approval_assigned
  Recipient  : approver (the assigned approver_id)
  Channel    : web push + in-app
  Priority   : action_required
  Message    : "Approval required: {workflow_name} — {step_description}"
  Action link: deep link to Pending Approvals panel in Workflow Dashboard

EVENT: approval_deadline_2h
  Recipient  : approver
  Channel    : web push
  Priority   : warning
  Message    : "Approval deadline in 2 hours: {workflow_name}"
  Trigger    : Supabase CRON Edge Function checks 2h before each deadline
  Action link: deep link to the specific approval

EVENT: approval_escalated
  Recipient  : new escalated approver
  Channel    : web push + in-app
  Priority   : action_required
  Message    : "Escalated to you: {workflow_name} approval from {original_approver_name}"
  Action link: deep link to Pending Approvals panel

EVENT: approval_auto_actioned
  Recipient  : original approver (the one who timed out)
  Channel    : in-app
  Priority   : info
  Message    : "Your pending approval for {workflow_name} was auto-{approved|rejected} due to timeout"

EVENT: workflow_completed
  Recipient  : trigger initiator (triggered_by user, or the employee in event-triggered workflows)
  Channel    : in-app
  Priority   : success
  Message    : "{workflow_name} completed successfully"

EVENT: workflow_failed
  Recipient  : trigger initiator + all users with role = 'workflow_admin' or 'super_admin'
  Channel    : web push
  Priority   : warning
  Message    : "{workflow_name} failed at step '{step_name}': {error_message}"
  Action link: deep link to Instance Detail (execution trace view)

EVENT: instance_cancelled
  Recipient  : trigger initiator
  Channel    : in-app
  Priority   : info
  Message    : "{workflow_name} instance was cancelled"
