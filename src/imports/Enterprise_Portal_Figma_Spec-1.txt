--- IT SERVICES RULES ---

TICKET CREATION:
  - Title: required, min 10 chars, max 200 chars
  - Category: required (drives SLA policy auto-selection)
  - Priority: required, default = P3-Medium
  - Reporter: auto-set to logged-in user, not editable by L1 agents
  - Assignee: optional on creation; if blank → auto-assign based on team on-call schedule
  - Description: optional but recommended; warn if blank (soft validation)
  - Attachments: max 10 files per ticket, max 10MB per file
    Allowed types: jpg, png, gif, pdf, docx, xlsx, txt, zip, log
  - On creation: SLA due_at auto-calculated = NOW + first_response_mins (from SLA policy)
  - Ticket number: auto-generated, format TKT-NNNN, not editable

TICKET STATUS TRANSITIONS (enforce in UI — only valid transitions allowed):
  Open        → In Progress | Pending | Cancelled
  In Progress → Pending | Resolved | Cancelled
  Pending     → In Progress | Closed | Cancelled
  Resolved    → Closed | Open (if reporter rejects resolution)
  Closed      → (no transitions — terminal)
  Cancelled   → (no transitions — terminal)
  RULE: Only assignee or manager can move to Resolved; only reporter or manager can Reopen

TICKET RESOLUTION:
  - Resolution summary: required (min 20 chars)
  - Resolution code: required (from lookup)
  - Cannot resolve if sub-tasks are open (warn, allow override with confirmation)
  - On resolve: trigger CSAT survey email to reporter after 2 hours
  - SLA: record resolution timestamp, calculate SLA met/missed

SLA RULES:
  - SLA clock starts on ticket creation (not assignment)
  - Pause SLA when status = Pending (awaiting user response)
  - Resume SLA when status changes from Pending back to In Progress
  - Business hours calculation: exclude weekends + holidays from SLA config
  - Breach detection: background job every 5 minutes checks due_at vs NOW
  - Once breached: cannot "un-breach" even if resolved immediately (historical record)

PRIORITY CHANGE RULES:
  - P1 (Critical): requires manager approval OR a linked S1 defect
  - Priority escalation: auto-escalate to next level if unassigned >50% of first_response_mins
  - Downgrade: only allowed by team lead or above

LINKING RULES:
  - A ticket can link to max 20 items total (across all entity types)
  - Cannot link a ticket to itself
  - Circular linking check: if A links to B, B cannot link to A as "duplicates"
  - When linking to a Defect: copy defect severity to ticket priority recommendation (warn, don't auto-set)

KB ARTICLE RULES:
  - Must have category
  - Title: required, min 10 chars, unique within category
  - Draft articles: only visible to agents and above
  - Published articles: visible to all users
  - Cannot delete a published article (archive instead)
  - Helpful/Not Helpful: each user can vote once, can change vote

--- ASSET MANAGEMENT RULES ---

ASSET CREATION:
  - Asset Tag: auto-generated format AST-NNNN, unique, not editable after save
  - Name: required, min 3 chars, max 255 chars
  - Category: required (drives depreciation rate, warranty defaults)
  - Serial Number: optional but if entered must be unique across all assets
  - Purchase Cost: must be > 0 if entered; numeric only
  - Warranty End: must be >= Purchase Date
  - Status on creation: defaults to "In Stock"

ASSET ASSIGNMENT RULES:
  - Can only assign assets with status: In Stock | Active (not Under Maintenance, Retired, etc.)
  - One asset can only be assigned to ONE user or ONE team at a time (not both)
  - Cannot assign to deactivated user
  - Assignment date: cannot be in the future (assignment is current)
  - Expected return date: must be > assignment date if provided
  - On assignment: asset status auto-changes to "Assigned"
  - On return: must specify condition; if condition = Damaged → auto-create maintenance request (warn)
  - Return date: cannot be before assignment date

DEPRECIATION RULES:
  - Current Value = Purchase Cost × (1 - depreciation_rate) ^ age_in_years
  - Depreciation rate pulled from Asset Category config
  - If current value < 0 → set to 0
  - Recalculate nightly via background job

WARRANTY ALERTS:
  - Alert triggers configured in Master Data (default: 30 days + on expiry)
  - Alert sent to: IT Admin + asset assignee
  - If warranty already expired at time of asset creation → immediate alert

MAINTENANCE RULES:
  - Cannot log maintenance for Retired/Disposed assets
  - If maintenance type = Corrective: create linked IT ticket (optional, prompt user)
  - Maintenance cost: numeric only, no negatives
  - Next due date: must be >= performed date
  - Recurring schedule: min frequency = 7 days (no daily maintenance scheduling)
  - On overdue maintenance (next_due_at < TODAY): auto-flag, appear in dashboard alerts

ASSET RETIREMENT:
  - Must specify reason: End of Life | Damaged Beyond Repair | Surplus | Donated | Sold
  - If asset is currently assigned: must be returned first (block with error)
  - Retired assets: read-only, cannot be reassigned or modified (except adding documents)

--- PROJECT MANAGEMENT RULES ---

PROJECT RULES:
  - Project Key: auto-generated from name (first letters, uppercase, max 6 chars), editable once before first sprint
  - Name: required, min 3 chars, unique per organization
  - Owner: required, cannot remove owner without assigning a new one
  - End date: must be > start date
  - Cannot archive a project with an active sprint (complete sprint first)
  - Only Owner/Admin can delete; deletion requires confirming project name by typing it

BACKLOG ITEM RULES:
  - Title: required, min 5 chars, max 500 chars
  - Type: required (Story/Epic/Spike/Research)
  - Story Points: whole numbers only, from configured scale (e.g., Fibonacci)
  - Epic items: cannot be assigned to a sprint directly (must break into stories first)
  - Epic hierarchy: max 2 levels (Epic > Story); stories cannot have child stories
  - Status transitions:
    Open → In Progress | Cancelled
    In Progress → In Review | Blocked | Open (revert)
    In Review → Testing | In Progress (revert)
    Testing → Done | In Progress (failed)
    Done → (terminal unless sprint rollback)
    Blocked → In Progress (unblock)
  - Sprint assignment: item can only be in ONE sprint at a time
  - When sprint completed: unfinished items auto-moved to backlog (not next sprint), user confirms

DEFECT RULES:
  - Title: required, min 5 chars
  - Severity: required
  - S1 Defects: must be assigned within 2 hours of creation; alert if unassigned > 1 hour
  - S1/S2 Defects: auto-notify project owner + team lead on creation
  - Status transitions:
    Open → In Progress | Deferred | Won't Fix
    In Progress → Fixed | Open (revert) | Blocked
    Fixed → Verified | In Progress (regression found)
    Verified → Closed
    Deferred/Won't Fix → Open (reopen)
    Closed → Open (regression — must provide reason)
  - Cannot close defect without entering "Fixed in version"
  - Regression flag: if defect reopened → automatically mark regression = true

TASK RULES:
  - Title: required
  - Estimated hours: must be > 0 if entered; max 40h per task (split if larger)
  - Sub-tasks: max 10 sub-tasks per parent task
  - Cannot mark parent task Done if sub-tasks are incomplete (warn, allow override)
  - Dependencies: no circular dependencies (A blocks B, B cannot block A)

SPRINT RULES:
  - Only ONE active sprint per project at a time
  - Sprint start date: cannot be in the past (same day is OK)
  - Sprint end date: must be > start date; min 5 days, max 30 days
  - Cannot start sprint with 0 items
  - Sprint goal: recommended, warn if blank (soft validation, not blocking)
  - Completing a sprint: must handle all unfinished items (move to backlog or next sprint)
  - Velocity: auto-calculated = sum of story points of Done items at sprint completion

TIME LOGGING RULES:
  - Hours: min 0.5, max 12 per single log entry (cannot log > 12h in one entry)
  - Logged date: cannot be in the future; cannot be > 90 days in the past
  - Can log time against: tasks, backlog items, defects only (not epics)
  - Multiple entries per day allowed (different tasks)
  - Total logged > estimated: show warning, allow override
  - Weekend logging: allowed but flagged with visual indicator

--- CROSS-APP RULES ---

CROSS-APP LINKING:
  - IT Ticket ↔ Backlog Item: bidirectional; creating link in one app reflects in the other
  - IT Ticket ↔ Defect: bidirectional
  - IT Ticket ↔ Asset: one-directional from ticket (asset shows linked tickets read-only)
  - Cannot link entities from different organizations (multi-tenant guard)
  - Link removal: removing from either side removes both sides of the link

NOTIFICATIONS:
  - User can configure per-notification-type preferences (email on/off, in-app on/off)
  - Notification preferences stored per user per app context
  - Digest mode: user can choose Real-time | Hourly Digest | Daily Digest
  - @mentions: always real-time, cannot be turned off
  - SLA breach alerts: always real-time for assignee + team lead, cannot be turned off

PERMISSIONS (cross-app):
  - Admin: full access all apps
  - Manager: create/edit/delete own team's items; view all
  - Agent/Member: create/edit own items; view team items
  - Viewer: read-only across all apps
  - Reporter (IT only): create tickets, view own tickets only
  - Cross-app navigation: user must have at least Viewer on target app

DATA INTEGRITY:
  - Deleting a user: reassign open tickets/tasks first (block deletion if active items exist)
  - Deleting a project: must archive all sprints and move tickets linked to project items
  - Deactivating a user: keeps historical data, removes from assignment pickers
