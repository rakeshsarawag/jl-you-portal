G3 — REPLACE POLLING WITH SUPABASE REALTIME
------------------------------------------------------------------------
Problem:
  setInterval polls every 15 seconds. Notifications are delayed and create
  unnecessary network load.

Approach:
  1. Remove all setInterval / clearInterval polling logic from NotificationBell.tsx.

  2. On component mount — keep initial fetch:
       GET /notifications?userId={currentUser.id}&limit=50&is_read=false

  3. Set up Supabase Realtime subscription after mount:

       const channel = supabase
         .channel('user-notifications')
         .on(
           'postgres_changes',
           {
             event: 'INSERT',
             schema: 'public',
             table: 'notifications',
             filter: `user_id=eq.${currentUser.id}`
           },
           (payload) => {
             addNotification(payload.new);       // prepend to local state
             triggerBrowserPush(payload.new);    // G7 push hook
           }
         )
         .subscribe();

  4. On component unmount:
       return () => { supabase.removeChannel(channel); }

  5. Bell badge count:
    - Derived reactively from unread count in local React state.
    - Updated by: Realtime INSERT events, G2 mark-read mutations, G9 bulk delete.

  6. Error handling:
    - If Realtime subscription fails (CHANNEL_ERROR), fall back to 60-second polling
      with console.warn. Do not silently fail.

G6 — SNOOZE / REMIND LATER
------------------------------------------------------------------------
Problem:
  No way to temporarily dismiss a notification and have it resurface later.

Approach:
  1. Database: add snoozed_until TIMESTAMPTZ column to notifications table.

  2. Snoozed notifications are excluded from:
    - Bell dropdown list
    - Bell unread count badge
    - Notification history page default view (unless "Show Snoozed" filter is on)

  3. Re-surfacing:
    - Supabase Realtime: subscribe to UPDATE events on notifications table where
      snoozed_until <= now() AND is_read = false.
    - Alternatively: on each dropdown open, re-fetch to catch newly unsnoozed items.

  4. Snooze UI:
    - On hover of a notification row, show [💤 Snooze ▾] icon button on the right side.
    - Click opens a small dropdown menu (portal-rendered to avoid overflow clipping):
        30 minutes
        1 hour
        Tomorrow 9:00 AM
        Next Monday 9:00 AM
    - Snooze times computed in user's local timezone.

  5. API:
    PUT /notifications/{id}/snooze
    Body: { snoozed_until: "2026-09-05T09:00:00+05:30" }

  6. Snoozed management:
    - Accessible at /notifications/preferences under a "Snoozed Notifications" section.
    - Lists all currently snoozed notifications with: title, snoozed_until datetime, [Unsnooze] button.
    - [Unsnooze]: PUT /notifications/{id}/snooze with { snoozed_until: null }

  7. Validation: snoozed_until must be > now() and <= now() + 7 days.

------------------------------------------------------------------------
G7 — VAPID SETUP VERIFICATION + PUSH HARDENING
------------------------------------------------------------------------
Problem:
  VAPID keys may not be configured in the Supabase Edge Function environment.
  Push failures are not communicated to the user.

Approach:
  1. Environment verification:
    - Confirm VAPID_PUBLIC_KEY and VAPID_PRIVATE_KEY are set in Supabase Edge Function
      environment variables (Dashboard → Edge Functions → Secrets).
    - VAPID_SUBJECT should also be set (e.g. mailto:admin@yourapp.com).

  2. usePushNotifications hook improvements:
    - Wrap Notification.requestPermission and pushManager.subscribe in try/catch.
    - If permission === 'denied': set state to 'blocked'; stop attempting push.
    - If VAPID_PUBLIC_KEY missing (env var not set): log warning; set state to 'unconfigured'.
    - Graceful degradation: if push unavailable for any reason, app continues with
      in-app notifications only (no thrown errors, no broken UI).

  3. Bell dropdown — "Enable Desktop Notifications" prompt:
    - If Notification.permission === 'default' (not yet asked):
      Show a soft banner inside the dropdown (indigo-50 bg, indigo border):
        [🔔 Enable Desktop Notifications] → click triggers requestPermission()
    - If permission === 'denied': show a gray informational note:
        "Desktop notifications are blocked. Enable in browser settings."
    - Hide banner once permission is granted.

  4. Push subscription storage:
    - On successful subscription: POST /notifications/push-subscription
    - Body: { endpoint, p256dh_key, auth_key, user_agent }
    - Upsert by (user_id, endpoint) — replace keys if same endpoint re-subscribes.
    - Table: user_push_subscriptions (see Section 3)

  5. Server-side push delivery (Supabase Edge Function):
    - Triggered by Supabase Realtime INSERT on notifications table.
    - Before sending: check notification_preferences (event not disabled for push).
    - Before sending: check notification_quiet_hours (not in quiet window).
    - Use web-push library with VAPID keys to deliver to all active subscriptions
      for the target user_id.

NOTIFICATIONS TABLE — ADD COLUMNS
-----------------------------------
  ALTER TABLE notifications ADD COLUMN IF NOT EXISTS
    type           VARCHAR NOT NULL DEFAULT 'info'
                   CHECK (type IN ('info', 'warning', 'action_required', 'success')),
    app_filter     VARCHAR NOT NULL DEFAULT 'all'
                   CHECK (app_filter IN (
                     'dashboard', 'directory', 'recruitment', 'onboarding', 'user-mgmt',
                     'performance', 'training', 'communications', 'collaboration', 'workflow',
                     'it-services', 'assets', 'projects'
                   )),
    entity_type    VARCHAR,          -- leave | candidate | employee | course | workflow_approval | etc.
    entity_id      UUID,             -- FK to related entity
    deep_link      VARCHAR,          -- e.g. /workflow-dashboard?instance=123
    is_read        BOOLEAN NOT NULL DEFAULT false,
    read_at        TIMESTAMPTZ,
    snoozed_until  TIMESTAMPTZ,
    action_data    JSONB;            -- e.g. {"approval_id": "uuid", "approve_url": "/...", "reject_url": "/..."}

  -- Indexes
  CREATE INDEX IF NOT EXISTS idx_notifications_user_app
    ON notifications(user_id, app_filter);

  CREATE INDEX IF NOT EXISTS idx_notifications_user_unread
    ON notifications(user_id, is_read) WHERE is_read = false;

  CREATE INDEX IF NOT EXISTS idx_notifications_snooze
    ON notifications(snoozed_until) WHERE snoozed_until IS NOT NULL;


NEW TABLE: notification_preferences
-------------------------------------
  CREATE TABLE notification_preferences (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id      UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    app          VARCHAR NOT NULL,       -- same values as app_filter
    event_key    VARCHAR NOT NULL,       -- e.g. 'leave_approval_required', 'dm_received'
    in_app       BOOLEAN NOT NULL DEFAULT true,
    push         BOOLEAN NOT NULL DEFAULT true,
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (user_id, app, event_key)
  );


NEW TABLE: notification_quiet_hours
--------------------------------------
  CREATE TABLE notification_quiet_hours (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE UNIQUE,
    start_time  TIME NOT NULL,           -- e.g. '22:00:00'
    end_time    TIME NOT NULL,           -- e.g. '08:00:00'
    timezone    VARCHAR NOT NULL,        -- IANA timezone e.g. 'Asia/Kolkata'
    is_active   BOOLEAN NOT NULL DEFAULT true,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
  );


NEW TABLE: user_push_subscriptions
--------------------------------------
  CREATE TABLE user_push_subscriptions (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id       UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    endpoint      TEXT NOT NULL,
    p256dh_key    TEXT NOT NULL,
    auth_key      TEXT NOT NULL,
    user_agent    TEXT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    last_used_at  TIMESTAMPTZ,
    UNIQUE (user_id, endpoint)
  );

================================================================================
SECTION 6 — VALIDATION RULES
================================================================================

QUIET HOURS:
  - start_time must not equal end_time (no zero-duration quiet period)
  - timezone must be a valid IANA timezone string (validate against Intl.supportedValuesOf('timeZone'))
  - Spans midnight are valid (e.g. 22:00 to 08:00 = next day morning)

NOTIFICATION PREFERENCES:
  - (user_id, app, event_key) must be unique (enforced by DB unique constraint)
  - push cannot be true if in_app is false (push depends on in_app)
  - Locked events (is_locked = true in event config): cannot set in_app = false

PUSH SUBSCRIPTIONS:
  - endpoint must be unique per user — upsert behavior: if same (user_id, endpoint) exists, update keys
  - endpoint must be a valid HTTPS URL
  - p256dh_key and auth_key must be non-empty Base64URL strings

BULK DELETE:
  - All notification IDs in the request must belong to auth.uid() (server enforces)
  - Maximum 500 IDs per bulk operation; return HTTP 400 if exceeded
  - Filter-based bulk delete (e.g. all read) also capped at 500 per call

SNOOZE:
  - snoozed_until must be > now() (cannot snooze in the past)
  - snoozed_until must be <= now() + 7 days (max snooze duration)
  - Cannot snooze a notification that is already read (business rule; warn user)

NOTIFICATIONS INSERT (server-side, all apps posting notifications):
  - type must be one of: info | warning | action_required | success
  - app_filter must be a valid app slug (no 'all' allowed on insert)
  - user_id must reference a valid auth.users(id)
  - title: max 200 chars; body: max 500 chars


================================================================================
SECTION 7 — CROSS-APP INTEGRATION
================================================================================

ALL APPS → NOTIFICATION BELL
------------------------------
  Every app (Workflow, Training, Collaboration, etc.) posts notifications via:

  POST /api/notifications
  Headers: Authorization: Bearer {service_role_key}
  Body:
  {
    "user_id"      : "uuid",
    "title"        : "Leave Approval Required",
    "body"         : "Asha Sharma — Sick Leave Apr 10–12 (3 days)",
    "type"         : "action_required",
    "app_filter"   : "workflow",
    "entity_type"  : "workflow_approval",
    "entity_id"    : "uuid-of-approval",
    "deep_link"    : "/workflow-dashboard?instance=abc123",
    "action_data"  : { "approval_id": "uuid", "approve_url": "/...", "reject_url": "/..." }
  }

NOTIFICATION BELL → WEB PUSH
------------------------------
  Flow triggered on INSERT in notifications table (via Supabase Realtime in Edge Function):
  1. Look up notification_preferences for (user_id, app_filter, event_key).
     If in_app = false: skip storage (or store with is_suppressed flag).
     If push = false: store notification but skip push delivery.
  2. Check notification_quiet_hours for user_id.
     If current time (in user timezone) is within quiet window: skip push only.
  3. Fetch all active push subscriptions for user_id from user_push_subscriptions.
  4. For each subscription: call web-push.sendNotification() with VAPID credentials.
  5. Handle 410 Gone (expired subscription): delete from user_push_subscriptions.

WORKFLOW → NOTIFICATION BELL
------------------------------
  Trigger: approval step assigned to a user
  Creates: action_required notification
  action_data: { "approval_id": "uuid", "approve_url": "/api/approvals/{id}/approve", "reject_url": "/api/approvals/{id}/reject" }
  Bell renders: inline [✓ Approve] [✗ Reject] buttons in notification row
  On button click:
    POST /api/approvals/{approval_id}/approve (or /reject)
    On success: mark notification as read + replace buttons with status chip "Approved" / "Rejected"

COLLABORATION → NOTIFICATION BELL
-----------------------------------
  Trigger: DM received OR @mention in channel
  Creates: info notification (DM) or info/warning notification (@mention)
  deep_link: /collaboration/channels/{channel_id}?message={message_id}
  On click: navigate to deep_link + mark notification as read

ALL NOTIFICATION INLINE ACTIONS → APP APIS
--------------------------------------------
  Inline actions (Approve/Reject in bell dropdown) call the respective app's REST endpoint.
  On completion:
  1. Mark notification as read: PUT /notifications/{id}/read
  2. Update notification row UI to show result status chip (no full re-fetch needed)
