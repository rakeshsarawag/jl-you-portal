SECTION 5 — VALIDATION & BUSINESS RULES
================================================================================

PROJECT CREATION:
  - Name: required, 3-100 chars, unique within org
  - Start Date must be ≤ End Date
  - Manager: required
  - Budget if entered: must be > 0, max 999,999,999
  - Cannot delete project with active sprint (must complete or cancel sprint first)
  - Only admin can delete projects

SPRINT RULES:
  - Only one sprint can be Active per project at a time
  - Cannot start sprint without sprint goal (required)
  - Sprint dates cannot overlap with another sprint in same project
  - Sprint must have at least 1 backlog item committed before it can be started
  - Complete Sprint: all In Progress items must be moved (next sprint or backlog) — cannot abandon mid-item
  - Velocity = story points of items moved to Done status before sprint end
  - Reopening a completed sprint: admin only, requires reason

BACKLOG ITEMS:
  - Story points: must be from selected PM_STORY_POINT_SCALES values (not free text)
  - Epic link: one item can only belong to one epic
  - Moving item from Active sprint: allowed only for manager/admin with confirmation dialog
  - Adding item to Active sprint (mid-sprint): allowed, flagged as "Added mid-sprint" for velocity accuracy
  - Closing a Story: requires all child Sub-tasks to be Done first
  - Closing an Epic: requires all linked stories to be Done or Won't Do

TASKS:
  - Due date cannot be before project start date
  - Sub-task due date cannot exceed parent task due date
  - Estimated hours: max 200 per task
  - Logged hours: cannot log future date (only today or past)
  - Deleting a task with logged hours: soft delete only (archive flag), not physical delete
  - Assigning a task: notifies assignee

MILESTONES:
  - Due date must be within project start/end range
  - Cannot mark Achieved before due date without confirmation ("Early completion confirmed?")
  - Missed is auto-flagged when due date passes and status is still Pending/At Risk
  - Auto-flag job runs daily: sets status = 'At Risk' when 7 days before due and status = 'Pending'

RISKS:
  - Risk Score = PM_RISK_LIKELIHOODS.value × PM_RISK_IMPACTS.value
  - Status cannot go back to 'Identified' from 'Mitigated' or 'Closed'
  - 'Triggered' status: notify project manager and risk owner immediately

BUDGET:
  - Alert at 70%: notify project manager
  - Alert at 90%: notify project manager + admin
  - Alert at 100%: block further time logging with billable=true (warn, allow override for manager)
  - Burn rate = (spent / days elapsed) × total sprint days remaining = projected spend

RAG STATUS:
  - Manual change only (not auto-calculated, but health score can suggest)
  - Every change logged: who | old | new | timestamp
  - Red RAG: triggers notification to admin

ROLE ENFORCEMENT:
  employee:
    - View projects they are a member of (not all projects)
    - Log time on assigned tasks only
    - Cannot change project RAG, status, budget, dates
    - Cannot add/remove team members
    - Can create tasks (assigned to self) in sprints they are part of
  manager:
    - All of above plus: create/edit projects, manage team, start/complete sprints
    - Can change RAG, status, milestone status
    - Cannot delete projects
  admin:
    - Full CRUD including delete
    - Can force-complete sprints, reopen milestones
    - Can override budget alerts

  - Asset status visible in project overview
