  ENTITY: LEAVE_TYPES
--------------------------------------------------------------------------------

  Purpose:
    Defines all leave categories available in the organization. These records

--------------------------------------------------------------------------------
  ENTITY: LEAVE_POLICIES
--------------------------------------------------------------------------------

  Purpose:
    Provides department-level or employment-type-level overrides on top of
    the base LEAVE_TYPES configuration. When a policy row exists for a given
    (leave_type_id, department, employment_type) combination, the override
    values supersede the base type values for balance and accrual calculations.

  Fields:
    policy_id              UUID, primary key
    leave_type_id          UUID, foreign key -> leave_types.type_id
    department             VARCHAR(100), nullable  -- NULL means applies to all depts
    employment_type        VARCHAR(50), nullable   -- NULL means all employment types
    accrual_override       NUMERIC(5,2), nullable  -- overrides base accrual_rate
    max_balance_override   NUMERIC(5,2), nullable
    carry_forward_override NUMERIC(5,2), nullable
    effective_from         DATE, not null

  Usage Notes:
    - The system resolves the most specific matching policy at runtime:
      (leave_type_id + department + employment_type) > (type + department) >
      (type + employment_type) > base leave_type record.
    - Seed rows are created by HR Admin during initial configuration.
      Representative examples:
        - Interns: Earned Leave max_balance_override = 6, carry_forward_override = 0
        - Contract staff: Sick Leave accrual_override = 6 (half-year entitlement)
        - Engineering dept: Casual Leave carry_forward_override = 2

  ENTITY: ATTENDANCE_SHIFT_TYPES
--------------------------------------------------------------------------------

  Purpose:
    Defines the shift schedules used for attendance tracking, late-mark
    calculation, and OT/Comp-Off eligibility. Linked to employee records via
    the Employee Directory app.

  Fields:
    shift_id             UUID, primary key
    name                 VARCHAR(100), not null, unique
    start_time           TIME
    end_time             TIME
    grace_period_mins    INTEGER, default 0
    break_duration_mins  INTEGER, default 60
    weekly_off_days      INTEGER[], -- array of day numbers: 0=Sun, 6=Sat
    is_flexi             BOOLEAN, default false
    core_hours_start     TIME, nullable  -- only relevant for flexi shifts
    core_hours_end       TIME, nullable  -- only relevant for flexi shifts

  Seed Data:

    1. General Shift
       start_time          : 09:00
       end_time            : 18:00
       grace_period_mins   : 15
       break_duration_mins : 60
       weekly_off_days     : [0, 6]  (Sunday, Saturday)
       is_flexi            : false
       core_hours_start    : NULL
       core_hours_end      : NULL

    2. Flexi Shift
       start_time          : NULL  (employee logs any start within 07:00–11:00)
       end_time            : NULL  (9-hour window from chosen start)
       grace_period_mins   : 0
       break_duration_mins : 60
       weekly_off_days     : [0, 6]
       is_flexi            : true
       core_hours_start    : 11:00
       core_hours_end      : 15:00
       notes               : Employee must be present during core window.
                             Total logged hours must be >= 9h per day.

    3. Night Shift
       start_time          : 21:00
       end_time            : 06:00  (next calendar day)
       grace_period_mins   : 15
       break_duration_mins : 60
       weekly_off_days     : []  (rotating; configured per employee record)
       is_flexi            : false
       core_hours_start    : NULL
       core_hours_end      : NULL
       notes               : Night shift differential rules managed separately
                             in payroll config.

    4. Early Shift
       start_time          : 07:00
       end_time            : 16:00
       grace_period_mins   : 15
       break_duration_mins : 60
       weekly_off_days     : [0, 6]
       is_flexi            : false
       core_hours_start    : NULL
       core_hours_end      : NULL

    5. Half Day Shift
       start_time          : 09:00 (first half) / 14:00 (second half)
       end_time            : 13:00 (first half) / 18:00 (second half)
       grace_period_mins   : 10
       break_duration_mins : 0
       weekly_off_days     : [0, 6]
       is_flexi            : false
       notes               : Two logical sub-slots; the half-day selection is
                             captured at leave application time, not as separate
                             shift records.

--------------------------------------------------------------------------------
  ENTITY: COMPETENCY_FRAMEWORKS
--------------------------------------------------------------------------------

  Purpose:
    Defines the competency model applied to employees during performance reviews.
    Frameworks are matched to employees by designation title pattern. Each
    competency has five proficiency levels with descriptor text, used during
    rating calibration.

  Fields:
    framework_id    UUID, primary key
    name            VARCHAR(100), not null
    role_pattern    VARCHAR(200)  -- regex matched against designation title
    competencies    JSONB         -- array of competency objects (see structure below)

  Competency Object Structure:
    {
      competency_id    : UUID,
      name             : VARCHAR,
      description      : TEXT,
      proficiency_levels: [
        { level: 1, label: "Foundational",  descriptor: "..." },
        { level: 2, label: "Developing",    descriptor: "..." },
        { level: 3, label: "Proficient",    descriptor: "..." },
        { level: 4, label: "Advanced",      descriptor: "..." },
        { level: 5, label: "Expert",        descriptor: "..." }
      ]
    }

  Seed Framework 1: Individual Contributor
    role_pattern  : ^(Intern|Trainee|Junior Analyst|Analyst|Senior Analyst|Lead)$
    Competencies  :
      - Technical Expertise
          Measures depth and currency of domain and technical knowledge relevant
          to the role.
          L1: Basic awareness of concepts. L2: Applies knowledge with supervision.
          L3: Works independently; delivers quality output.
          L4: Considered a go-to resource by peers. L5: Sets technical direction.

      - Problem Solving
          Measures analytical thinking and solution design under ambiguity.
          L1: Identifies straightforward problems when pointed out.
          L2: Breaks down structured problems with guidance.
          L3: Independently diagnoses and resolves moderately complex issues.
          L4: Designs solutions for systemic or cross-functional problems.
          L5: Resolves novel, high-impact problems with lasting solutions.

      - Communication
          Clarity, conciseness, and appropriateness of written and verbal
          communication.
          L1: Communicates basic information clearly in familiar contexts.
          L2: Structures messages for intended audience with some guidance.
          L3: Communicates proactively and adapts style to context.
          L4: Influences through communication; leads critical conversations.
          L5: Exemplary communicator; represents org externally.

      - Collaboration
          Effectiveness in teamwork, sharing knowledge, and supporting peers.
          L1: Participates when asked. L2: Actively contributes to team goals.
          L3: Builds relationships and helps others. L4: Fosters inclusion and
          removes blockers for team. L5: Creates a culture of collaboration.

      - Ownership & Initiative
          Degree of accountability taken and proactiveness shown.
          L1: Completes assigned tasks on time.
          L2: Raises issues proactively; takes ownership of deliverables.
          L3: Drives tasks end-to-end without hand-holding.
          L4: Anticipates org needs; initiates improvements unprompted.
          L5: Inspires ownership culture; holds team accountable.

  Seed Framework 2: Manager
    role_pattern  : ^(Manager|Senior Manager|Director|VP|C-Suite)$
    Competencies  :
      - Leadership
          Ability to inspire, direct, and develop a high-performing team.
          L1: Manages own work; beginning to guide others.
          L2: Leads small team; sets clear expectations.
          L3: Leads a functional team; manages performance actively.
          L4: Leads multiple teams or large function.
          L5: Visionary leader; influences org-wide culture and direction.

      - Strategic Thinking
          Capacity to think beyond the immediate and align work to business goals.
          L1: Understands team goals within dept context.
          L2: Connects team work to department strategy.
          L3: Contributes to department-level strategy.
          L4: Shapes functional strategy; considers competitive landscape.
          L5: Drives org-wide strategy with multi-year horizon.

      - People Development
          Investment in growing direct reports and building talent pipeline.
          L1: Gives basic feedback when asked.
          L2: Conducts regular 1:1s; identifies development needs.
          L3: Creates individual development plans; coaches actively.
          L4: Builds successors; advocates for team members' growth org-wide.
          L5: Develops next-generation leaders; builds people programs.

      - Decision Making
          Speed, quality, and accountability in making and owning decisions.
          L1: Makes low-risk decisions with guidance.
          L2: Makes routine decisions independently; escalates appropriately.
          L3: Makes complex decisions under uncertainty; communicates rationale.
          L4: Makes high-stakes decisions; manages risk and fallback.
          L5: Makes org-defining decisions; navigates ambiguity at scale.

      - Communication
          (same structure as Individual Contributor framework — see above)

      - Business Acumen
          Understanding of financial drivers, market dynamics, and org economics.
          L1: Understands team budget basics.
          L2: Manages team budget; understands P&L concepts.
          L3: Owns cost center; drives efficiency.
          L4: Understands competitive and market dynamics.
          L5: Influences business model; drives revenue or cost strategy.

      - Execution
          Ability to translate strategy into results reliably.
          L1: Delivers assigned tasks on schedule.
          L2: Delivers team commitments; manages blockers.
          L3: Runs programs end-to-end; mitigates delivery risk.
          L4: Delivers complex cross-functional programs.
          L5: Consistently delivers org-level strategic initiatives on time.

  ENTITY: REVIEW_RATING_SCALES
--------------------------------------------------------------------------------

  Purpose:
    Defines the numeric scales used in performance reviews. Multiple scales
    can be configured; a cycle record references the scale to use.

  Fields:
    scale_id    UUID, primary key
    name        VARCHAR(100), not null
    levels      JSONB  -- array of level objects

  Level Object Structure:
    { value: INTEGER, label: VARCHAR, description: TEXT, color: VARCHAR(7) }

  Seed Scale 1: 5-Point Scale
    Name   : Standard 5-Point Rating Scale
    Levels :
      value: 1 | label: Unsatisfactory        | color: #DC2626 (red)
        description: Performance is significantly below role expectations.
                     Immediate corrective action required.
      value: 2 | label: Below Expectations    | color: #EA580C (orange)
        description: Performance partially meets expectations. Improvement
                     plan recommended.
      value: 3 | label: Meets Expectations    | color: #2563EB (blue)
        description: Performance consistently meets role requirements.
                     Employee is effective in their position.
      value: 4 | label: Exceeds Expectations  | color: #16A34A (green)
        description: Performance frequently surpasses role requirements.
                     Employee delivers notable impact beyond scope.
      value: 5 | label: Outstanding           | color: #7C3AED (purple)
        description: Exceptional and consistent performance. Role model for
                     the organization; significant business impact delivered.

  Seed Scale 2: 3-Point Scale
    Name   : Simplified 3-Point Rating Scale
    Levels :
      value: 1 | label: Needs Improvement
        description: Performance does not yet meet core role expectations.
      value: 2 | label: Meets Expectations
        description: Performance is aligned with role requirements.
      value: 3 | label: Exceeds Expectations
        description: Performance goes above and beyond requirements.

--------------------------------------------------------------------------------
  ENTITY: OFFER_LETTER_TEMPLATES
--------------------------------------------------------------------------------

  Purpose:
    HTML-based offer letter templates with named placeholders. The system
    populates placeholders at offer generation time from the candidate and
    job requisition records.

  Fields:
    template_id              UUID, primary key
    name                     VARCHAR(100), not null
    html_body                TEXT  -- full HTML content with placeholders
    applicable_employment_type VARCHAR(50)  -- maps to employment_types.name

  Supported Placeholders:
    {candidate_name}       Full name of the candidate
    {position}             Job title / designation
    {department}           Department name
    {salary_ctc}           Annual CTC (Cost to Company)
    {basic_salary}         Monthly basic salary component
    {joining_date}         Expected date of joining
    {reporting_manager}    Name of the assigned reporting manager
    {probation_period}     Probation duration (e.g., "6 months")
    {work_location}        Office location or "Remote"
    {offer_validity_date}  Date by which candidate must accept the offer

  Seed Templates:
    1. Standard Full-time Offer
       applicable_employment_type: Full-time
       Key clauses to include:
         - Position and department confirmation
         - CTC breakdown (basic, HRA, special allowance, PF, gratuity)
         - Probation period (typically 6 months)
         - Code of conduct and NDA reference
         - Joining formalities checklist

    2. Intern Offer Letter
       applicable_employment_type: Intern
       Key clauses to include:
         - Internship duration and department
         - Stipend amount
         - Learning objectives
         - IP and confidentiality clause
         - No employment guarantee clause

    3. Contract Offer Letter
       applicable_employment_type: Contract
       Key clauses to include:
         - Contract start and end dates
         - Scope of work
         - Rate/fee structure
         - Termination notice period
         - Intellectual property assignment


--------------------------------------------------------------------------------
  ENTITY: ONBOARDING_CHECKLIST_TEMPLATES
--------------------------------------------------------------------------------

  Purpose:
    Pre-defined task sequences for onboarding a new employee. Templates can
    be scoped by department, designation level, and employment type. When an
    onboarding record is created, tasks are instantiated from the matching
    template and assigned due dates based on the employee's joining date plus
    the day offset.

  Fields:
    template_id         UUID, primary key
    name                VARCHAR(100), not null
    department          VARCHAR(100), nullable  -- NULL = all departments
    designation_level   INTEGER, nullable       -- NULL = all levels
    employment_type     VARCHAR(50), nullable   -- NULL = all types
    tasks               JSONB  -- array of task objects

  Task Object Fields:
    task_id             UUID
    title               VARCHAR(200)
    description         TEXT
    owner               ENUM('HR', 'IT', 'Manager', 'Employee', 'Finance')
    due_day_offset      INTEGER  (days after joining date)
    category            ENUM('Documents', 'IT', 'Training', 'Access',
                              'Orientation', 'Finance')
    is_mandatory        BOOLEAN
    depends_on_task_id  UUID, nullable  -- task that must complete first

  Seed Template: Default Onboarding
    name               : Default Onboarding
    department         : NULL (applies to all)
    designation_level  : NULL
    employment_type    : NULL

    Task List:

      Day 0  |  Submit Government ID Documents
               owner: Employee | category: Documents | mandatory: true
               description: Employee submits copies of Aadhaar, PAN, passport,
               and any other identity documents required for HR records.

      Day 0  |  Sign Offer Letter and NDA
               owner: Employee | category: Documents | mandatory: true
               description: Employee countersigns the offer letter and the
               Non-Disclosure Agreement via the portal or in person.

      Day 0  |  IT Laptop and Equipment Allocation
               owner: IT | category: IT | mandatory: true
               description: IT team provisions and hands over laptop,
               accessories, and any role-specific hardware.

      Day 1  |  System Access Setup
               owner: IT | category: Access | mandatory: true
               depends_on: "IT Laptop and Equipment Allocation"
               description: Create corporate email, configure VPN access,
               set up required collaboration tools, and provision application
               access per role permissions.

      Day 1  |  Office Orientation and Tour
               owner: HR | category: Orientation | mandatory: true
               description: HR walks the new employee through the office
               floor, facilities, safety exits, cafeteria, and meeting rooms.

      Day 1  |  Introduction to Manager and Team
               owner: Manager | category: Orientation | mandatory: true
               description: Reporting manager introduces the employee to the
               immediate team, shares team norms, and explains the 30/60/90-day
               expectations.

      Day 3  |  Enroll in Mandatory Compliance Training
               owner: HR | category: Training | mandatory: true
               description: HR assigns POSH, Information Security, and Code of
               Conduct training through the Training module. Employee must
               complete within 30 days.

      Day 7  |  Complete Employee Profile in Directory
               owner: Employee | category: Documents | mandatory: true
               description: Employee fills in the full profile in the Employee
               Directory app: photo, bio, skills, emergency contact, bank
               details, and address proof.

      Day 7  |  HR Policies Walkthrough
               owner: HR | category: Orientation | mandatory: true
               description: HR conducts a session covering leave policy,
               attendance, WFH norms, expense reimbursement, and grievance
               redressal procedures.

      Day 14 |  Meet Assigned Buddy for Knowledge Sharing
               owner: Employee | category: Orientation | mandatory: false
               description: Employee connects with their assigned buddy
               (experienced peer) for a knowledge transfer session on team
               processes and unwritten norms.

      Day 30 |  Complete Onboarding Assessment
               owner: HR | category: Training | mandatory: true
               depends_on: "Enroll in Mandatory Compliance Training"
               description: Employee completes the onboarding assessment quiz
               covering compliance, policies, and tools introduced during the
               first month.

      Day 90 |  Probation Review Meeting with Manager
               owner: Manager | category: Orientation | mandatory: true
               description: Manager conducts the formal probation review.
               Outcome is recorded (confirmed / extended / not confirmed)
               and triggers the relevant Supabase workflow event.

================================================================================
  SECTION A2 — PERMISSIONS CONFIGURATION
  (Role-Based Access Control matrix and feature-level permission keys)
================================================================================


--------------------------------------------------------------------------------
  SYSTEM ROLES
  (Ordered by authority level, highest to lowest)
--------------------------------------------------------------------------------

  1.  Super Admin
      Full system access. Can configure all apps, manage all roles, override
      any setting. Typically 1-2 IT/HR leads.

  2.  HR Admin
      Full HR operations access. Can manage employee records, run payroll
      exports, configure master data, manage all leave and attendance.

  3.  HR Manager
      Manages HR processes and team. Approves escalated leave requests.
      Can view (but not always edit) financial data. Cannot change system
      config.

  4.  Department Manager
      Manages employees within their department. Approves leave and WFH for
      their direct reports. Can view department-level analytics.

  5.  Team Lead
      Manages direct reports at the squad/team level. Can approve leave for
      direct reports (within policy limits). Limited analytics access.

  6.  Recruiter
      Manages the full recruitment pipeline: job postings, candidates,
      interviews, offers. Cannot manage employee records post-hire.

  7.  Trainer
      Manages training courses, learning paths, enrollments, and compliance
      reports. Cannot manage employee records.

  8.  Finance Manager
      Can view salary bands, approve encashments, view cost center data.
      Cannot manage HR processes.

  9.  IT Admin
      Manages system access provisioning, MFA, user sessions, audit logs.
      Cannot manage HR content.

  10. Employee (default)
      Access to own data only: leave, attendance, directory profile,
      performance self-review, enrolled training, collaboration channels.

--------------------------------------------------------------------------------
  DEFAULT AUTO-ASSIGNMENT RULES
  (Applied automatically by system hooks at specified lifecycle events)
--------------------------------------------------------------------------------

  TRIGGER: New Employee Record Created

    Action 1: Assign system role "Employee" to the new user account.
    Action 2: Enroll employee in the "All Employees" communication channel.
    Action 3: Enroll employee in their department's default team collaboration
              channel (e.g., #engineering, #hr, #sales).
    Action 4: Create an onboarding record using the best-matching
              ONBOARDING_CHECKLIST_TEMPLATE based on department, designation
              level, and employment type.
    Action 5: Send a welcome notification to the employee's email with
              portal login instructions.

  TRIGGER: User Assigned HR Department in Directory

    Action: Prompt Super Admin to grant HR Manager role. The role elevation
            requires explicit Super Admin confirmation and cannot be
            auto-assigned without it. A pending role review task is created
            in User Management.

  TRIGGER: User Assigned IT Department in Directory

    Action: Prompt Super Admin or existing IT Admin to grant IT Admin role.
            Same confirmation requirement as HR Manager above.

  TRIGGER: Onboarding Record Marked Complete
    (All mandatory tasks for an onboarding record are in state "Completed")

    Action 1: Activate the employee's system access to all apps permitted
              under the Employee role.
    Action 2: Fire the "onboarding_completed" workflow trigger event.
    Action 3: If employment type is "On Probation", schedule a
              "probation_review_due" event notification 7 days before the
              probation end date.
    Action 4: Send a congratulatory notification to the employee and a
              completion summary to the HR Manager.

  TRIGGER: Employee Role Changed to Full-time
    (After probation confirmation)

    Action 1: Update leave balance entitlements to full-time accrual rates.
    Action 2: Re-evaluate applicable WFH policy and update accordingly.
    Action 3: Unlock any full-time-only features or channels.

  TRIGGER: Employee Exit Initiated

    Action 1: Fire the "employee_exit_initiated" workflow trigger event.
    Action 2: Auto-create an offboarding checklist instance (mirroring the
              onboarding template but with exit-specific tasks: asset return,
              access revocation, final settlement, exit interview).
    Action 3: Assign revocation tasks to IT Admin.
    Action 4: Assign final settlement tasks to Finance Manager.
    Action 5: Set a system flag to block new leave applications and WFH
              requests for this employee beyond the last working day.

  ADDITIONAL CONSTRAINT RULES:

    - A user cannot hold both "HR Manager" and "IT Admin" roles simultaneously.
      The system must warn and require Super Admin override if attempted.
    - "Super Admin" role can only be granted by another existing Super Admin.
      It cannot be self-assigned and cannot be bulk-imported.
    - Deactivating a "Department Manager" role without assigning a replacement
      triggers a warning: leave approvals for their department will be
      escalated to HR Manager until a new manager is designated.
    - All role changes are recorded in the User Management audit log with
      timestamp, changed-by user, and reason (free text field, required).
