SECTION 1 — FIX PLAN (KNOWN GAPS)
--------------------------------------------------------------------------------

G1 — Cascade View: Drag-to-Reparent (Priority: Medium)
  Problem : Cascade view is display-only; parent-child relationships cannot
            be changed from the UI.
  Solution:
    - Enable drag-and-drop on OKR nodes in cascade view using a dnd library
      (e.g. @dnd-kit/core or react-beautiful-dnd).
    - On drag of an OKR node onto another OKR node:
        Show confirmation dialog:
          "Set '{dragged_okr_title}' as a child of '{target_okr_title}'?"
          [Confirm] [Cancel]
    - On confirm: PUT /okr/okrs/{id}  body: { aligned_to_okr_id: newParentId }
    - Circular parent guard (client + server):
        Before sending request, walk the ancestor chain of newParentId.
        If the dragged OKR appears anywhere in that chain, reject with:
          "Cannot set parent — this would create a circular alignment."
        Server must also enforce this check.
    - Visual feedback: ghost image while dragging; drop target highlights green
      on valid drop, red on invalid (circular / same node).

G4 — Undo Delete: Restore Key Results and Progress History (Priority: Medium)
  Problem : Undo delete restores the OKR row only; key results and check-in
            history are lost permanently.
  Solution:
    - On delete, before calling DELETE API, capture full OKR snapshot:
        {
          okr: { ...all fields },
          key_results: [ ...all KR rows for this OKR ],
          checkins: [ ...all okr_checkins rows for this OKR ]
        }
    - Store snapshot in React state (undo stack, max 5 items).
    - Show undo toast: "OKR deleted. [Undo] (10 s)"
    - On Undo:
        1. POST /okr/okrs  — re-create the OKR (new id or restore original id
           depending on DB soft-delete strategy)
        2. For each key result: POST /okr/key_results
        3. For each check-in snapshot: POST /okr/checkins
        4. Refresh list view.
    - If server uses soft-delete (deleted_at column), undo = PATCH with
      deleted_at: null — simpler and preferred.

G2 — Timeline Tab: Gantt-Style View (Priority: Low)
  Problem : No visual timeline showing OKR durations and overlap.
  Solution:
    - Add "Timeline" tab to the OKR app side nav.
    - Horizontal Gantt chart:
        Y-axis : OKRs grouped by owner (owner name as section header).
        X-axis : months spanning the active cycle's start_date to end_date.
        Bars   : each OKR rendered as a horizontal bar from start_date to
                 end_date. Bar color by level:
                   company    = purple  (#7C3AED)
                   department = blue    (#2563EB)
                   team       = teal    (#0D9488)
                   individual = gray    (#6B7280)
        KR milestones: diamond markers on the bar at the KR's expected
                       completion date (if set).
        Today line: vertical red dashed line at today's date.
    - Zoom controls: [Month] [Quarter] [Year]
    - Hover tooltip on bar: OKR title | owner | score | start-end dates.
    - Clicking a bar navigates to that OKR's detail/card in List view.

G3 — Confidence Chart in Check-In History (Priority: Low)
  Problem : Check-in confidence levels are recorded but never visualised.
  Solution:
    - In the OKR detail drawer / check-in history section, add a line chart

    - X-axis : check-in dates (chronological).
    - Y-axis : confidence_level 1–5.
    - One line per Key Result (different color per KR).
    - Dot markers on each check-in point; hover shows date, KR title,

SECTION 2 — FEATURE ENHANCEMENTS (INDUSTRY STANDARD)
--------------------------------------------------------------------------------

2.1 OKR HIERARCHY
  Levels: company | department | team | individual
  Stored in: okrs.level (enum)

  Visibility rules:
    company OKRs    : visible to everyone; non-admin/non-manager = read-only.
    department OKRs : visible to members of that department.
    team OKRs       : visible to members of that team.
    individual OKRs : employee sees own only; manager/HR/admin sees all.

  Alignment ("aligned_to_okr_id"):
    An individual OKR can be aligned to any parent OKR at any level above it.
    This replaces the prior "parentId" concept — same mechanism, renamed for
    clarity. The aligned_to_okr_id is a self-referential FK on the okrs table.
    Alignment is optional; unaligned OKRs are still valid.

  UI: alignment selector on OKR create/edit form — searchable dropdown showing
  OKRs at higher levels. Cascade view renders the full alignment tree.

2.2 OKR CYCLES (CONFIGURABLE)
  Master Data table: OKR_CYCLES
    cycle_id    | UUID PK
    name        | text (e.g. "Q2 2026", "Annual 2026")
    type        | enum: Annual | Semi-Annual | Quarterly
    start_date  | date
    end_date    | date
    status      | enum: Planning | Active | Review | Closed
    fiscal_year | integer (e.g. 2026)

  Default seed cycles for 2026:
    Q1 2026  — Jan 1 – Mar 31   — Quarterly — Closed
    Q2 2026  — Apr 1 – Jun 30   — Quarterly — Active
    Q3 2026  — Jul 1 – Sep 30   — Quarterly — Planning
    Q4 2026  — Oct 1 – Dec 31   — Quarterly — Planning
    Annual 2026 — Jan 1 – Dec 31 — Annual  — Active

  Cycle status rules:
    Planning : OKRs can be drafted (draft status) but not checked in.
    Active   : OKRs can be created, updated, and checked in.
    Review   : No new OKRs; grading and closing allowed.
    Closed   : Read-only. No create, update, check-in, or grade changes
               (unless admin override with reason).

  OKR form: cycle selector (dropdown of non-Closed cycles).
  Cycle selector (top of List view): filters displayed OKRs by cycle.

  Cycle Analytics (visible in Cycles tab and Executive Dashboard OKR tab):
    - Completion %: count(is_closed=true) / count(total) per cycle.
    - Avg score: average of okrs.score for the cycle.
    - Top performers: top 5 employees by avg_score in okr_cycle_scores.

2.3 SCORING METHODOLOGY
  Key Result score (decimal 0.0 – 1.0, stored in key_results.score):
    score = (current_value - start_value) / (target_value - start_value)
    Capped at 1.0 (100% achievement cap for scoring; actual value can reach
    120% per validation rule).
    For boolean KRs: 0.0 or 1.0.

  OKR score (decimal 0.0 – 1.0, stored in okrs.score):
    score = average of all key_results.score values for that OKR.
    Recomputed on every check-in update.

  Color bands (stored in OKR_SCORING_THRESHOLDS master data):
    0.0 – 0.39 : Behind      | red    | grade F / D
    0.4 – 0.59 : Progressing | amber  | grade C
    0.6 – 0.69 : On Track    | yellow-green | grade B-
    0.7 – 1.0  : Achieved    | green  | grade A / B

  Grade auto-suggestion (manager can override):
    A  : score >= 0.80
    B  : score >= 0.60 and < 0.80
    C  : score >= 0.40 and < 0.60
    D  : score >= 0.20 and < 0.40
    F  : score < 0.20

  Grade display: badge on OKR card (A=green, B=blue, C=yellow, D=orange, F=red)

2.4 CHECK-IN CADENCE
  Push notification reminders: configurable per employee (weekly / biweekly).
  Default: weekly, sent on Monday 9:00 AM local time.

  Check-in form (per OKR):
    - For each Key Result:
        currentValue  : number input (unit shown as label)
        confidence    : 1–5 star/dot selector
    - Notes          : textarea (optional)
    - has_blocker    : checkbox "Flag a blocker"
    - If has_blocker: blocker_description textarea (required if flagged)
    - [Submit Check-In] button

  Blocker notification:
    If has_blocker = true on submit:
      → Push notification to OKR owner's direct manager:
        type: okr_blocker_flagged
        message: "{employee_name} flagged a blocker on '{okr_title}'"

  Check-in history (in OKR detail view):
    - Table: date | KR | value at check-in | confidence | notes | blocker?
    - Line chart of confidence_level over time per KR (see G3 fix).
    - Value progression bar: shows current_value moving toward target_value
      over time.

2.5 BULK END-OF-QUARTER ACTIONS
  Available to: manager (for their team), HR, admin.

  Location: Cycles tab → click [Manage] on any cycle in Review or Active status.

  Bulk Grade screen:
    Shows table: OKR Title | Owner | Score | Auto-Suggested Grade | Override Grade
    All rows show auto-suggested grade pre-filled.
    Manager can override grade inline (dropdown A/B/C/D/F).
    [Grade All] button: saves all overridden/auto grades in one POST.
    [Close All] button: grades all ungraded OKRs (auto-grade), sets
      all okrs.is_closed = true for this cycle, sets cycle.status = Closed.
    [Export Scorecard] button: exports Excel/CSV with all OKRs, scores,
      grades for the cycle.

  Closing cycle:
    1. All OKRs in cycle with no manual grade: auto-grade applied based on score.
    2. All OKRs: is_closed = true.
    3. Cycle: status = Closed.
    4. okr_cycle_scores rows created/updated per employee.
    5. Sync scores to performance_reviews (see cross-app integrations).
    6. Push notification: okr_cycle_closed → all employees with OKRs in cycle.

2.6 OKR TEMPLATES
  Master Data table: OKR_TEMPLATES
    template_id     | UUID PK
    name            | text
    type            | enum: personal | team | company
    level           | enum: company | department | team | individual
    objective_text  | text
    key_results     | JSONB array of { title, unit, target_value, start_value }
    is_active       | boolean (default true)

  Seed templates:
    1. "Increase Product Quality"
       Level: team | Type: team
       KRs: Reduce bug count from 50 to 10 (unit: bugs)
            Increase test coverage from 60% to 90% (unit: %)
            Achieve NPS score of 45 (unit: NPS)

    2. "Improve Customer Satisfaction"
       Level: department | Type: team
       KRs: Increase CSAT from 3.5 to 4.5 (unit: score)
            Reduce support response time from 24h to 4h (unit: hours)
            Resolve 95% of tickets within SLA (unit: %)

    3. "Grow Team Capabilities"
       Level: team | Type: team
       KRs: Complete 3 training certifications per person (unit: certifications)
            Achieve 100% completion of mandatory training (unit: %)
            Conduct 4 knowledge sharing sessions (unit: sessions)

    4. "Revenue Growth"
       Level: company | Type: company
       KRs: Increase MRR from ₹50L to ₹75L (unit: ₹ Lakhs)
            Acquire 50 new enterprise customers (unit: customers)
            Reduce churn from 8% to 4% (unit: %)

  Quick-create flow:
    [+ New OKR] → dialog shows [From Template] tab + [From Scratch] tab.
    From Template: searchable list of active templates.
    Select → pre-fills objective, KRs (editable before saving).

2.7 REPORTS AND ANALYTICS
  Accessible from Analytics tab in OKR app sidebar.

  Department OKR Health:
    Horizontal bar chart: one bar per department showing avg OKR score.
    Color-coded by band (red/amber/yellow-green/green).
    Filter by cycle.

  Individual Performance:
    Table: employee name | total OKRs | on-track count | avg score | grade.
    Sortable. Export to Excel.

  Alignment Coverage:
    KPI card: "% of individual OKRs aligned to company or dept OKR."
    Donut chart: aligned vs unaligned.
    Target: > 80% alignment.

  Exports:
    PDF Scorecard per employee: uses window.print() with print-specific CSS.
      Shows: employee name, cycle, OKR list, KR details, scores, grades.
    Excel export of all OKRs: uses SheetJS (xlsx library).
      Columns: OKR Title | Level | Owner | Dept | Cycle | Score | Grade |
               Start | End | Key Results (concatenated) | Is Closed.

3.1 okrs TABLE — added columns:
  level             | enum('company','department','team','individual')  NOT NULL DEFAULT 'individual'
  cycle_id          | UUID FK -> okr_cycles.cycle_id  NOT NULL
  score             | DECIMAL(3,2)  DEFAULT 0.00  -- computed, range 0.00-1.00
  aligned_to_okr_id | UUID FK -> okrs.id  NULLABLE  -- self-referential
  start_date        | DATE NOT NULL

  department_id     | UUID FK -> departments.id  NULLABLE  -- for dept-level OKRs

3.2 key_results TABLE — added columns:
  start_value       | DECIMAL(12,4)  DEFAULT 0
  current_value     | DECIMAL(12,4)  DEFAULT 0
  target_value      | DECIMAL(12,4)  NOT NULL
  unit              | VARCHAR(50)    -- e.g. "%", "units", "₹ Lakhs", "score"
  score             | DECIMAL(3,2)   DEFAULT 0.00  -- computed
  confidence_level  | SMALLINT       -- 1-5, latest check-in value (denormalised)
  is_boolean        | BOOLEAN        DEFAULT false  -- boolean KR (done/not done)

3.3 NEW TABLE: okr_checkins
  id                  | UUID PK DEFAULT gen_random_uuid()
  okr_id              | UUID FK -> okrs.id  NOT NULL
  kr_id               | UUID FK -> key_results.id  NULLABLE  -- null = OKR-level note
  checked_by          | UUID FK -> employees.id  NOT NULL
  check_date          | DATE NOT NULL DEFAULT CURRENT_DATE
  current_value       | DECIMAL(12,4)
  confidence_level    | SMALLINT  CHECK (confidence_level BETWEEN 1 AND 5)
  notes               | TEXT
  has_blocker         | BOOLEAN DEFAULT false
  blocker_description | TEXT  -- required if has_blocker=true
  created_at          | TIMESTAMPTZ DEFAULT NOW()
  INDEX: (okr_id, check_date)
  INDEX: (kr_id, check_date)

3.4 NEW TABLE: okr_cycles
  cycle_id    | UUID PK DEFAULT gen_random_uuid()
  name        | VARCHAR(100) NOT NULL
  type        | enum('Annual','Semi-Annual','Quarterly')  NOT NULL
  start_date  | DATE NOT NULL
  end_date    | DATE NOT NULL
  status      | enum('Planning','Active','Review','Closed')  DEFAULT 'Planning'
  fiscal_year | SMALLINT NOT NULL
  created_at  | TIMESTAMPTZ DEFAULT NOW()
  UNIQUE(name, fiscal_year)

3.5 NEW TABLE: okr_cycle_scores
  id            | UUID PK DEFAULT gen_random_uuid()
  cycle_id      | UUID FK -> okr_cycles.cycle_id  NOT NULL
  employee_id   | UUID FK -> employees.id  NOT NULL
  avg_score     | DECIMAL(3,2)
  grade         | CHAR(1)  CHECK (grade IN ('A','B','C','D','F'))
  total_okrs    | SMALLINT DEFAULT 0
  completed_okrs| SMALLINT DEFAULT 0
  scored_at     | TIMESTAMPTZ DEFAULT NOW()
  UNIQUE(cycle_id, employee_id)

3.6 NEW TABLE: okr_templates  (also managed via Master Data app)
  template_id    | UUID PK DEFAULT gen_random_uuid()
  name           | VARCHAR(200) NOT NULL
  type           | enum('personal','team','company')
  level          | enum('company','department','team','individual')
  objective_text | TEXT NOT NULL
  key_results    | JSONB NOT NULL  -- array of {title, unit, target_value, start_value}
  is_active      | BOOLEAN DEFAULT true
  created_at     | TIMESTAMPTZ DEFAULT NOW()

3.7 NEW TABLE: okr_scoring_thresholds  (managed via Master Data app)
  threshold_id     | UUID PK DEFAULT gen_random_uuid()
  label            | VARCHAR(50)  -- "Behind", "Progressing", "On Track", "Achieved"
  min_score        | DECIMAL(3,2)
  max_score        | DECIMAL(3,2)
  color            | VARCHAR(20)  -- Tailwind color class or hex
  grade_equivalent | VARCHAR(5)   -- e.g. "F/D", "C", "B", "A"

SECTION 5 — VALIDATION RULES
--------------------------------------------------------------------------------

OKR Title         : required | min 10 chars | max 200 chars
Key Results       : min 1 per OKR | max 5 per OKR
Target Value      : target_value > start_value (for numeric KRs)
Check-in Value    : current_value cannot exceed target_value × 1.2
                    (cap at 120%; score is capped at 1.0 separately)
Closed OKR        : cannot check in; cannot edit; cannot add KRs
Closed Cycle      : cannot create new OKRs; cannot check in; cannot change grades
                    Admin override: allowed with mandatory reason field
Circular Alignment: cannot set aligned_to_okr_id if it creates a cycle in the
                    ancestor chain (check recursively up to depth 10)
Grading           : only manager of OKR owner, HR Admin, or Admin can grade
                    cannot grade own OKR as an employee
Reopen Closed OKR : not allowed for non-admin; admin must provide reason
                    (stored in okrs.reopen_reason)
Boolean KR score  : 0.0 if current_value = 0 | 1.0 if current_value >= 1
Cycle dates       : start_date < end_date; cycles of same type cannot overlap
                    in the same fiscal_year

SECTION 6 — CROSS-APP INTEGRATIONS
--------------------------------------------------------------------------------

OKR <-> Performance App (bidirectional):
  - performance_reviews table: add column okr_cycle_score DECIMAL(3,2),
    add column okr_cycle_id UUID FK -> okr_cycles.
  - On OKR cycle finalization (status -> Closed):
      UPSERT okr_cycle_scores for each employee.
      UPDATE performance_reviews SET okr_cycle_score = avg_score
        WHERE employee_id = X AND review_period matches cycle fiscal_year.
  - Performance review form: read-only OKR summary panel showing the
    employee's OKRs for the cycle, scores, and grades.
    Fetched via: GET /okr/cycle-scores?employee_id={id}&cycle_id={id}

OKR -> Executive Dashboard (one-way read):
  - Executive Dashboard OKR Tab reads:
      Company OKR progress: okrs WHERE level='company' AND cycle_id=activeCycle
      Dept breakdown: aggregate by department_id
      At-risk OKRs: okrs WHERE score < 0.4 AND is_closed=false
  - API endpoint: GET /okr/exec-summary?cycle_id={id}
    Returns: { company_avg_score, dept_breakdown[], top_aligned[], at_risk[] }

OKR -> Analytics App:
  - OKR health metrics available as a data source in Advanced Analytics:
      department_okr_health view | individual_okr_performance view
  - Exposed via: GET /analytics/okr-health?cycle_id={id}&dept_id={id}

OKR -> Notifications Bell (portal-wide):
  - okr_checkin_due, okr_behind, okr_blocker_flagged, okr_graded,
    okr_cycle_closing_7d, okr_cycle_closed, okr_aligned_to_updated
    all appear in the portal-wide notification bell (read from
    notifications table filtered by recipient user_id)

OKR -> Workflow Automation:
  - OKR blocker flag = trigger for approval/escalation workflow.
  - Trigger event: okr_blocker_created
  - Workflow: notify manager (step 1) → if not resolved in 48h, escalate
    to department head (step 2)
  - Configured as a workflow template in the Workflow Automation app:
    "OKR Blocker Escalation" template

SECTION 7 — PUSH NOTIFICATIONS (Web Push API / VAPID)
--------------------------------------------------------------------------------

All notifications stored in notifications table:
  id | user_id | type | title | body | link | is_read | created_at

Notification types and routing:

okr_checkin_due
  Trigger    : Scheduled job (weekly/biweekly per employee setting)
  Recipients : OKR owner (all employees with active OKRs in active cycle)
  Priority   : warning
  Title      : "Check-in reminder"
  Body       : "Weekly check-in due for your OKRs in Q{N} {year}"
  Link       : /okr-management?cycle={id}&action=checkin

okr_behind
  Trigger    : Scheduled job at cycle midpoint; recheck weekly
  Condition  : okrs.score < 0.4 AND is_closed=false AND cycle at midpoint
  Recipients : OKR owner + OKR owner's direct manager
  Priority   : warning
  Title      : "OKR falling behind"
  Body       : "'{okr_title}' is Behind — current score {score}"
  Link       : /okr-management?okr_id={id}

okr_blocker_flagged
  Trigger    : On check-in submit with has_blocker=true
  Recipients : OKR owner's direct manager
  Priority   : action_required
  Title      : "Blocker flagged on OKR"
  Body       : "{employee_name} flagged a blocker on '{okr_title}': {blocker_description_truncated}"
  Link       : /okr-management?okr_id={id}

okr_graded
  Trigger    : On grade saved (individual or bulk)
  Recipients : OKR owner
  Priority   : info
  Title      : "Your OKR has been graded"
  Body       : "'{okr_title}' received grade {grade} from {manager_name}"
  Link       : /okr-management?okr_id={id}

okr_cycle_closing_7d
  Trigger    : Scheduled job 7 days before cycle end_date
  Recipients : All employees with active (is_closed=false) OKRs in the cycle
  Priority   : warning
  Title      : "OKR cycle closing in 7 days"
  Body       : "Q{N} OKR cycle closes on {end_date} — complete your check-ins"
  Link       : /okr-management?cycle={id}

okr_cycle_closed
  Trigger    : On cycle status change to Closed
  Recipients : All employees with OKRs in the cycle
  Priority   : info
  Title      : "OKR cycle closed"
  Body       : "Q{N} {year} OKR cycle is now closed — view your scorecard"
  Link       : /okr-management?cycle={id}&tab=history

okr_aligned_to_updated
  Trigger    : On parent OKR title or description update
  Recipients : Owner(s) of child OKRs aligned to the updated parent
  Priority   : info
  Title      : "Parent OKR updated"
  Body       : "Parent OKR '{parent_title}' was updated by {updater_name}"
  Link       : /okr-management?okr_id={parent_id}
