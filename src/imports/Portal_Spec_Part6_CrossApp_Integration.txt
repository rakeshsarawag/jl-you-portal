SCOPE
-----
This document defines ALL cross-app integrations for the portal, covering:
  - Group 1 (HR Apps): Employee Dashboard, Employee Directory, Recruitment,
    Onboarding, User Management, Performance (incl. OKRs), Training,
    Communications, Collaboration, Workflow Automation, Notification Bell
  - Group 2 (Business/Operations Apps): OKR Management (standalone), Executive
    Dashboard, Advanced Analytics, Security & Compliance, Advanced Features
    (incl. Documentation), Invoice Generation, Payroll Management

Shared infrastructure across ALL apps:
  - Supabase Auth (authentication + JWT)
  - Permissions App (RBAC, role-based permission keys)
  - Master Data App (configuration, lookup values)
  - Notification Bell (push notification delivery)
  - Workflow Automation (approval and trigger-based workflows)

SECTION A: COMPLETE CROSS-APP INTEGRATION MAP
================================================================================

Column legend:
  Source App     — app that initiates or owns the data / event
  Target App     — app that receives, displays, or acts on the event
  Trigger        — what causes the integration to fire
  Action         — what happens in the Target App
  Data Passed    — fields / payload transferred
  Sync Type      — realtime | event-driven | polling | scheduled | on-load
  Bidirectional  — yes / no (if yes, reverse flow described separately)

A1. PAYROLL ↔ EMPLOYEE DIRECTORY
--------------------------------------------------------------------------------

#  Source App          Target App          Trigger
   Payroll             Employee Directory  New salary structure created
   Action              Employee record updated with salary_band and current_ctc
   Data Passed         employee_id, salary_band, gross_salary, effective_date
   Sync Type           Event-driven (Supabase realtime on salary_structures insert)
   Bidirectional       Yes — see reverse below

#  Source App          Target App          Trigger
   Employee Directory  Payroll             Employee location set / changed
   Action              Payroll resolves Professional Tax state slab for that employee
   Data Passed         employee_id, location_id, state_code
   Sync Type           Event-driven
   Bidirectional       (above is the reverse)

#  Source App          Target App          Trigger
   Employee Directory  Payroll             Employee status set to "Inactive" / "Exited"
   Action              Payroll sets payroll_status = "suspended" for that employee
   Data Passed         employee_id, exit_date, exit_reason
   Sync Type           Event-driven (on employees.status update)
   Bidirectional       No

#  Source App          Target App          Trigger
   Employee Directory  Payroll             New employee record created (status = Active)
   Action              Payroll initialises payroll entry; payroll active from join month
   Data Passed         employee_id, join_date, department_id, designation_id, location_id
   Sync Type           Event-driven
   Bidirectional       No

#  Source App          Target App          Trigger
   Employee Directory  Payroll             Employee exit processed (offboarding complete)
   Action              Final payroll run triggered; LOP days = remaining working days
                       after last working day; full-and-final settlement flagged
   Data Passed         employee_id, last_working_date, lop_days
   Sync Type           Event-driven
   Bidirectional       No

A13. EXECUTIVE DASHBOARD → ALL APPS (READ-ONLY AGGREGATION)
--------------------------------------------------------------------------------

#  Source App          Target Apps         Trigger
   All apps            Executive Dashboard On-load / tab change / date filter applied
   Action              Executive Dashboard aggregates KPI data from:
                         Employee Directory  → headcount, attrition, org structure
                         Payroll             → payroll cost, avg salary, headcount
                         Invoice             → revenue, outstanding, overdue
                         Recruitment         → open positions, time-to-hire, offers
                         Training            → completion rate, compliance training %
                         OKR Management      → company/dept OKR scores
   Data Passed         Each domain exposes /api/analytics/<domain> endpoint
                       Exec Dashboard queries each with { period, department_id? }
   Sync Type           On-load; individual KPI cards refresh on Supabase realtime
                       subscription where applicable
   Bidirectional       No — Executive Dashboard NEVER writes back to any source app

   Drill-through:
     KPI cards include a "View in [App]" link that navigates to the source app
     with pre-applied filters (e.g. date range, department, status)
     Examples:
       "42 Open Positions" → /recruitment?status=open&period=current
       "Payroll Cost ₹18L" → /payroll?period=2026-08
       "3 Overdue Invoices" → /invoices?status=overdue

A15. SECURITY & COMPLIANCE ↔ ALL APPS (AUDIT LOGGING)
--------------------------------------------------------------------------------

#  Source App          Target App          Trigger
   Every app           Security            Any significant user action (see Section D)
   Action              Audit event written to audit_logs table via shared
                       useAuditLogger React hook (imported in every app)
   Data Passed         { actor_id, action, entity_type, entity_id, old_value?,
                         new_value?, ip_address, user_agent, timestamp,
                         severity: 'low'|'medium'|'high'|'critical' }
   Sync Type           Synchronous write (awaited before UI response)
   Bidirectional       Yes — Security app reads audit_logs;
                         Security alerts (critical events) push notifications to
                         IT Admin / HR Admin / Super Admin;
                         All apps' admin sections can query their own audit trail
                         via /api/audit-logs?entity_type=<domain>

   Security → Workflow:
     Compliance deadline approaching → triggers Compliance Deadline Reminder workflow
     Critical security event (severity = 'critical') → triggers Security Alert workflow
     Privacy request created → triggers Privacy Request Processing workflow

    Employee record = single source of truth for dashboard profile data
    Dashboard reads employee fields on load; no write-back

  Performance → Employee Directory
    Performance ratings stored against employee_id; Directory shows
    last_rating on employee profile (read-only badge)

  Recruitment → Employee Directory
    Candidate hired → employee record auto-created in Directory
    with source = "recruitment", candidate_id reference stored

  Recruitment → Onboarding
    Candidate hired → Onboarding task list auto-generated for new employee
    Data passed: employee_id, start_date, department_id, manager_id

  Training → Performance
    Training completions visible in Performance review context
    (employee_certifications read on form load)

  Communications → Notification Bell
    New announcement / event / poll → push notification to targeted employees

  Workflow Automation → Notification Bell
    Every workflow step requiring human action → push notification to assignee

  User Management → ALL apps
    Role assignment change → Supabase Auth metadata updated → all apps
    re-evaluate permissions on next page load (JWT refresh)

  Onboarding → Employee Dashboard
    Onboarding task list shows in Dashboard "My Tasks" widget until complete

D3. AUDIT LOG TABLE SCHEMA (reference)
--------------------------------------------------------------------------------

  Table: audit_logs
  Columns:
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid()
    actor_id        uuid REFERENCES auth.users(id)

    user_agent      text

  RLS: Super Admin, HR Admin, IT Admin, Finance Manager can SELECT all rows
       Each app can INSERT its own rows (service role key in Edge Function)
       No UPDATE or DELETE permitted on audit_logs (append-only)

SECTION F: RECOMMENDED APP MERGES / SIMPLIFICATIONS
================================================================================

--------------------------------------------------------------------------------
F1. OKR MANAGEMENT + PERFORMANCE — MERGE RECOMMENDED
--------------------------------------------------------------------------------

Reasoning:
  The HR Spec already defines OKRs as a tab within the Performance app.
  A standalone OKR Management app creates dual ownership of the okrs table,
  potential data duplication, and user confusion about where to set/track OKRs.
  Power users (managers, HR) would need to context-switch between two apps
  for what is fundamentally a single workflow.

Recommendation:
  Merge OKR Management INTO Performance app as a dedicated OKR Module.
  Performance app tabs become:
    Overview | Reviews | OKRs | Goals | 360 Feedback | PIPs | Cycles | Analytics

  The standalone /okr route remains as a thin app with:
    - Employee-facing "My OKRs" view (simple, no HR admin controls)
    - "Open in Performance ↗" link on all detail and edit views
    - Use case: employees who only need to update OKR check-ins without
      seeing the full Performance app interface

  Data model: no change — okrs table remains; both apps read from same source
  Permissions: can_manage_okr_cycles still enforced; OKR tab in Performance
               respects existing Performance permissions

  When to implement: before launch — avoid building duplicate OKR UI
  Effort: low (redirect + tab restructure in Performance app)

--------------------------------------------------------------------------------
F2. ADVANCED FEATURES + DOCUMENTATION — KEEP SEPARATE, LINK BIDIRECTIONALLY
--------------------------------------------------------------------------------

Reasoning:
  Advanced Features (Report Builder, Automation Studio, Integrations, Monitoring)
  is a power-user tool for IT Admins, Finance Managers, and Super Admins.
  Documentation is a content tool for all employees (help, FAQs, videos).
  Merging them would bury help content behind admin-only permissions.

Recommendation:
  Keep as separate apps at /advanced-features and /documentation.
  Link them bidirectionally:
    - Advanced Features TopNav includes [? Help] → Documentation for that app
    - Documentation Admin panel includes "Preview in App" links
    - Documentation search results include Advanced Features articles
      tagged for power users

--------------------------------------------------------------------------------
F3. EXECUTIVE DASHBOARD + ADVANCED ANALYTICS — KEEP SEPARATE, DRILL-THROUGH LINKS
--------------------------------------------------------------------------------

Reasoning:
  Executive Dashboard: C-suite audience, high-level KPIs, beautiful visual
  design, pre-defined views, limited interactivity.
  Advanced Analytics: HR/Finance power users, detailed data slicing, custom
  filters, anomaly detection, custom report builder.
  Same data, very different UX requirements and permission profiles.

Recommendation:
  Keep as separate apps at /executive-dashboard and /advanced-analytics.
  Add "View in Advanced Analytics →" drill-through links on every KPI card
  and chart in the Executive Dashboard. The drill-through pre-applies
  matching filters (date range, department) to the Analytics view.
  Executive Dashboard's "Export" action routes to Analytics for large exports
  to avoid re-implementing export logic.

G4. API ROUTE CONVENTIONS (for integration reference)
--------------------------------------------------------------------------------

All domain APIs follow the pattern:
  GET  /api/<domain>                  — list with filter params
  GET  /api/<domain>/:id              — single record
  POST /api/<domain>                  — create
  PUT  /api/<domain>/:id              — update
  DEL  /api/<domain>/:id              — delete (soft where applicable)

Analytics / aggregation endpoints:
  GET  /api/analytics/payroll         — payroll cost aggregates
  GET  /api/analytics/invoices        — invoice revenue aggregates
  GET  /api/analytics/okrs            — OKR health metrics
  GET  /api/analytics/employees       — headcount / attrition metrics
  GET  /api/analytics/recruitment     — hiring funnel metrics
  GET  /api/analytics/training        — completion / compliance rates

Cross-app search:
  GET  /api/search?q=&entity_type=    — multi-domain search (Advanced Features)

Audit logging:
  POST /api/audit-logs                — append audit event (service role only)
  GET  /api/audit-logs                — query (restricted; permission-checked)

Notifications:
  GET  /api/notifications             — current user's notifications
  POST /api/notifications/mark-read   — mark as read
  GET  /api/notifications/preferences — current user's preferences
  PUT  /api/notifications/preferences — update preferences
